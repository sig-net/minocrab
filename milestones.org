Circuit entry points as plain typed Rust fns (NEAR/dfinity-style
decorator over a non-macro CircuitArg/entry core), typed disclosure
declarations with generated tests, then rusty maps + literals. Standing
principle: real types over macro rewriting — macros only generate
impls/shims writable by hand. Zero circuit overhead throughout; every
phase gated on interface snapshot + row_snapshot + all differential
suites. LOOSENED (dmd 2026-08-15): where small overhead would buy a
clear ergonomic win, ASK dmd with the concrete numbers (rows/k, what
the API gains) instead of auto-rejecting — the tradeoff is his call;
zero overhead stays the default and the gates stay in place.

- A fork may only collapse where its divergence is LEXICAL. Item (d) above
  is the test: opt changed the spec in three places (derived changeNonce,
  injective domain separator, Poseidon refund commitments), and a spec
  divergence cannot be a profile. If those survive, opt stays a separate
  source and the honest answer to this milestone is "the vocabulary
  unifies, the fork does not".
- Every divergence ledger stays, asserted in BOTH directions. They are what
  makes a circuit leaving its predecessor's coverage an explicit edit; a
  collapse that removed a ledger would be trading a correctness instrument
  for line count, which is the wrong direction on this project's priority
  order.
Exit criteria: the opt artifact is written in the same vocabulary as the
port, with every remaining twin justified by a protocol or spec difference

* M19 — API safety survey and the fixes it ranks (dmd, 2026-08-16)
Commissioned mid-session: survey (a) obvious Rust API footguns — where a
Rust programmer thinks the compiler or build guarantees something it does
not (hard to use is fine; failing after typecheck but before deploy is
fine); (b) anywhere we generate the WRONG code, semantically different
from the equivalent Compact; (c) anything we can encode in the type system
so users make fewer mistakes. "This is a smart contract programming
language."
Survey: notes/api-safety-survey.org. THE METHOD, since it is reusable:
look where a test on WELL-FORMED INPUT CANNOT SEE THE ERROR. Two seams —
invariants stated in prose (`PRECONDITION`, "the caller's job"), and
compactc's own verified lowering rules (notes/builtin-lowering.org §9),
where anything compactc does automatically and we leave to the author is a
divergence whatever the differentials say. The prior for this was earned
the same day: three bugs of exactly that class were found and fixed, all
green on every differential the day before.
- [X] The survey itself.
      (DONE 2026-08-16. FOUR wrong-code findings and four footguns; the
      headline is that COMPACT EMITS `assert(a >= b)` BEFORE EVERY
      SUBTRACTION and we emit nothing — an author writes
