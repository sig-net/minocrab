# MinoCrab

A Rust eDSL for Midnight contracts, usable instead of Compact. Circuits are ordinary Rust functions that build ZKIR; the toolchain below ZKIR (proving, keys, the ledger) is Midnight's own.

## Status

This whole project is vibe coded. If you use it for Midnight applications that do stuff with money, your users will likely lose it, and neither you nor I will know why. Nothing has run on a live network, and nothing is published to crates.io yet ([PUBLISHING.md](PUBLISHING.md) has the publish set and its order; consume it as a git dependency for now).

What there is to weigh against that: the ported circuits are checked against compactc's own compiled artifacts, the frozen `(k, rows)` and interface tables cover all 227 circuits of the corpus, and the type system rules out specific error classes instead of testing for them. [VERIFICATION.md](VERIFICATION.md) says what each of those claims rests on and where the chain is cut. [BENCHMARK.md](BENCHMARK.md) has the dated proving-cost comparison against compactc, and [OPTIMIZATION.md](OPTIMIZATION.md) the levers behind it.

## A minimal example

A circuit is a function with a `#[circuit]` attribute. Its argument types are its range constraints (`Uint<128>` is a 128-bit range check), a private wire cannot reach a public output without `disclose_as::<Label>`, and the return type `Discloses<(..)>` is the disclosure manifest: a test generated by the macro fails if the circuit discloses a label the signature does not name. This is the circuit `declaring` from `crates/minocrab-std/tests/disclose.rs` (imports trimmed to what it uses), which compiles under `cargo test`:

```rust
use minocrab::{Circuit, Private};
use minocrab_std::{circuit, label, CircuitArg, Disclose, Discloses, Uint, B32};

label! {
    /// The id the request is filed under.
    RequestId = "request id";
    /// The amount, in the clear because the ledger writes it.
    Amount = "amount";
}

#[derive(CircuitArg)]
struct Request {
    request_id: B32<Private>,
    amount: Uint<128>,
}

#[circuit]
fn declaring(c: &mut Circuit, request: Request) -> Discloses<(RequestId, Amount)> {
    let request_id = request.request_id.disclose_as::<RequestId>(c);
    let amount = request.amount.disclose_as::<Amount>(c);
    let sum = c.add(request_id.hi, amount.field());
    c.assert_bits(sum, 129);
    Discloses::of(())
}
```

The `#[circuit]` attribute turns `declaring` into a function of no arguments that returns the `Compiled` circuit (its ZKIR and metadata); `minocrab-sim` runs it natively in `cargo test`, prices it, and cross-checks every accepted run against Midnight's reference VM. A contract crate depends on `minocrab-std` (which re-exports the eDSL and the macros) and on `minocrab-sim` as a dev-dependency.

## Features

Each row is a feature with no Compact equivalent or a different one; the last column is where it is written up.

| feature | what it does | where |
|---|---|---|
| Disclosure manifest | `Wire<Private>` reaches a public output only through `disclose_as`, and the label must be in the return type | `minocrab` crate docs; `crates/minocrab/src/disclose.rs` |
| Typed leaves | argument types are the range constraints; subtraction emits its underflow guard; a guarded-off read must say what its default means; a literal outside its operand's bound does not build | `minocrab-std` crate docs |
| Cost budget | `#[circuit(max_k = 14)]` generates a test that prices the circuit with Midnight's own cost model and fails above the ceiling | `minocrab-macros` docs |
| Variable-length arguments | `Bounded<T, MAX>` is a length limb plus a prefix; `NonEmpty<T, REST>` makes "at least one" a type; `fold` / `for_each` own the guard, so a dead slot's ledger ops are skipped. Compact has only the fixed `Vector<N, T>` | `crates/minocrab-std/src/vector.rs` |
| Blind ledger update | a `Hook` is a program the ledger runs after the body (`add`, `sub`, `max`, `min`, `copy`, `move_entry`, branches); it embeds no public input, so no landed transaction can make it stale. Every inline read is an `Assumed<T>` that the ledger refuses to store until `.stale(c)` names the assumption. Compact compiles every ledger read to a `popeq` and has no ledger-side compare-and-select | `crates/minocrab-std/src/{hook,assumed,blind}.rs`; `notes/hooks-design.org` |
| Contention-free outbox | `Outbox` is a `Pending` plus a `Stream` whose accumulator moves only by blind ops, so calls, emits and responses land in one block | `crates/minocrab-signet/src/evm_flow/outbox.rs`; `notes/stream-design.org` |
| Typed cross-contract calls | `#[interface]` declares a callee; every parameter is `Public`, so a forgotten `disclose` is a compile error; each interface crate commits the callee's artifact and a hash pin and checks slots, constraints and the compiled `.zkir` prefix against it. The entry point is bound (its hash is a constant of the call's claim, as compactc 0.36 compiles it); argument types are not | `minocrab-abi`, `minocrab-interface-gen`, `signet-signer-interface`; `notes/interface-crates.org` |
| Typed EVM calls and cross-chain requests | a Solidity call is a Rust type (selector, ABI words, return, gas limit, success rule); `Pending<Call, Env, WORDS>` is the ledger slot that files it and settles it with a `Succeeded` or `Failed` ticket, so mis-pairing a ticket and a slot does not compile. Every call is static-width; dynamic ABI types wait for a consumer | `minocrab-evm`, `minocrab-signet`; `signet-sim` is the MPC's reader and responder for round trips under `cargo test` |
| Per-recipient disclosure | `disclose_to` writes a value to the public ledger that only the holder of one registered Jubjub key can open, with no proof, circuit or transaction on the recipient's side. The honest claim is confidentiality, not forward secrecy | `crates/minocrab-contracts/src/disclosure.rs`; `notes/disclosure-model.org` |
| Borsh records | records are a published Borsh subset with golden vectors and an independent TypeScript implementation; Compact's FAB encoding stays for compatibility | `spec/borsh-subset.md`; `notes/borsh-format.org` |
| Const-generic families | circuit families are const generics, monomorphized by rustc | `notes/const-generics.org` |
| Direct ZKIR emission | native byte instructions instead of explode/rebuild chains, one-block hashes where the preimage fits | [OPTIMIZATION.md](OPTIMIZATION.md); measured in [BENCHMARK.md](BENCHMARK.md) |

One hazard the typed EVM calls cannot see: the MPC resolves a request as failed when the return data does not decode, so a non-conforming ERC-20 that returns nothing produces an attested failure for a transfer that moved the tokens. Until the callee's return shape is declared per token, a contract on that API needs a callee allow-list.

What Compact has and MinoCrab does not (only real gaps; candidates that failed the check are in `notes/readme-research.org`):

- Nested coin arms: `insertCoin` / `pushFrontCoin` reached through a nested path. Nesting itself works over every shape Compact accepts; only the coin arms at depth are missing, because no fixture circuit compiles one (`notes/coin-arms-nested-adts.org`).
- A machine-checked skeleton of the source language's static plumbing. Compact's Agda specification and MinoCrab's Lean models cover different things; [VERIFICATION.md](VERIFICATION.md) §5 compares them.

## The crates

Core, layered bottom to top:

- `minocrab-zkir` (L0): read, write and round-trip ZKIR, reusing `midnight-zkir`.
- `minocrab-ir` (L1): the typed circuit builder over ZKIR instructions, and the `Pass` trait.
- `minocrab` (L2): the eDSL core: wires, visibility, disclosure.
- `minocrab-ledger` (L2.5): Impact ledger-op emission, bit-identical public-input encoding.
- `minocrab-std` (L3): the standard library (hashing, ECDSA, Borsh, the ledger block as types), re-exporting the eDSL and the macros.
- `minocrab-macros`: `#[circuit]`, `#[contract]`, `#[interface]` and the derives.

Tooling:

- `minocrab-sim` (L5): the native simulator, disclosure reports, the per-region cost profiler and the `minocrab` CLI.
- `minocrab-taint`: the taint lint for hash-preimage limbs.
- `minocrab-abi`: the interface/artifact agreement checker.
- `minocrab-interface-gen`: a compactc artifact becomes an interface crate (CLI).
- `minocrab-bench`: the head-to-head proving harness behind [BENCHMARK.md](BENCHMARK.md).

Compatibility and escape hatches:

- `minocrab-compat`: compactc-shaped gadgets that ports of Compact contracts import, so a port stays byte-identical to compactc's output. Not the cheapest lowering.
- `minocrab-experimental`: hand-written Impact and other escape hatches beneath the typed API. Versioned 0.0.x, no compatibility promise.

Application libraries:

- `minocrab-evm`: typed EVM calls and Solidity ABI words (ERC-20, ERC-721, ERC-4626, WETH, USDT, Uniswap, Aave).
- `minocrab-signet`: the Signet protocol for circuits: records, `Pending`, the outbox.

Interface crates (one per callee contract):

- `signet-signer-interface`: the signet signer.
- `signet-responder-interface`: the signet responder, the contract the MPC posts to.
- `xcall-target-interface`: an example generated from a contract nobody ported; the regeneration fixture for `minocrab-interface-gen`.

Signet support:

- `signet-protocol`: the protocol facts the contract, the artifact pipeline and the MPC all read.
- `signet-hashing`: the protocol's off-circuit hashes.
- `signet-artifacts`: the managed key and artifact directory for the signer circuits.
- `signet-sim`: the MPC's reader and responder as a pure function, for tests.
- `minocrab-publisher`: the MPC's Midnight publisher, pure core.

Not published:

- `minocrab-contracts`: the corpus of ports, demos and fixtures, and the suites that pin MinoCrab to compactc.

Beside the crates: `corpus/` holds the pinned Compact sources and the compactc artifacts compiled from them ([corpus/README.org](corpus/README.org)); `spec/` holds the Borsh-subset specification, golden vectors and the generated TypeScript.

## Build and test

The pinned toolchain (rust, compactc, the dev tools) comes from the nix flake; `direnv allow`, or `nix develop`, gives you the devshell. The build itself is plain cargo.

```
cargo test
```

is the routine loop (dependencies are optimized under the dev profile). `--release` is for the heavy gates: the frozen row snapshot, elevated `PROPTEST_CASES` runs and the benchmark. The gates and what each one means are in [VERIFICATION.md](VERIFICATION.md); the working loop for a change is in [CONTRIBUTING.md](CONTRIBUTING.md).

Terms you will meet in the first hour:

- **Impact**: Midnight's on-chain VM; a circuit emits its op stream as guarded public inputs, which the ledger re-executes and checks.
- **FAB**: field-aligned binary, Midnight's encoding of typed values as field-element limbs. A `Bytes<32>` is two limbs `[hi, lo]` (1 + 31 bytes); a `bytes n` atom is `ceil(n/31)` limbs, leftover first.
- **k / rows**: Halo2 cost. `rows` is occupied rows, `k` the log2 of the padded table. Prove time and RAM track 2^k, not rows, so a row cut only pays when it crosses a power-of-two boundary.
- **Guarded**: an op under a branch condition. The guard is an operand of the Impact instruction, and a false guard absorbs zeros.
- **`.bytes()`**: the one way out of a value-meaning newtype; grep for it to find every place a distinction is deliberately dropped.

## Porting kit

Rewrite a Compact contract in the eDSL and the harness checks it against compactc's artifact, not against your reading of the source. The check is statement identity: the same typed schema and the same public-input stream on one shared `ProofPreimage`, both runs handed to Midnight's reference VM; instruction streams may differ. `minocrab_sim::assert_call_compatible(ours, theirs, preimage)` is that check as one public function. A new port adds a scenario builder and one call; [VERIFICATION.md](VERIFICATION.md) §2(c) lists the differential suites already wired this way.

## Using MinoCrab as a library

Like the [GHC API](https://hackage.haskell.org/package/ghc), MinoCrab exposes its innards so you build tooling on it without forking. Rust users get `minocrab_sim::profile()` in a `#[test]`, criterion, and the row snapshot as a regression gate. Other users get the `minocrab` CLI in `minocrab-sim`: `minocrab rows <file.zkir>...` and `minocrab diff <a> <b>` report `(k, rows)` over any ZKIR file, MinoCrab's or compactc's.

Stability tiers (each crate's docs open with its own tier statement):

| tier | what | where |
|---|---|---|
| **stable** | the eDSL authoring core (`Circuit` and its instruction methods, `Wire`/`AnyWire`, the typed leaves, the FAB alignment types, `Compiled`/`IrSource`) | `minocrab`, `minocrab-std` |
| **stable** | the `Pass` trait and reference passes; the taint lint | `minocrab_ir::passes`; `minocrab-taint` |
| **stable** | the measurement API: `cost`, `profile`, `assert_max_k`, the calibrated `rowcost` tables, the `minocrab` CLI | `minocrab-sim` |
| **internal** | the raw `Builder`/`Val` layers, the simulator VMs (compiled unconditionally; no stability promise) | `minocrab-ir`, `minocrab-sim` |
| **internal** | the Impact ledger-op layer, the interface generator | `minocrab-ledger`, `minocrab-interface-gen` |

The wider contract-authoring surface (ledger declarations, kernel, Borsh, disclosure vocabulary) is not yet under the stability promise; the line widens by decision, never by accident. [PUBLISHING.md](PUBLISHING.md) has the per-crate stability of the publish set.

Three ways to extend it, no fork:

1. A super-optimised gadget: a crate on `minocrab-std` that builds a fragment (a keccak, a Merkle path, an ABI encoder) in fewer rows than the stdlib's. This is where the speed is: typed-layer instruction selection needs the type information ZKIR has erased. Prove it equivalent with the differential or spec harness.
2. An optimisation pass: implement `minocrab_ir::passes::Pass`, a pure, total `Vec<Instruction> -> (Vec<Instruction>, Vec<String>)`, and compose with `passes::run_pipeline`. Passes see type-erased ZKIR, so they are the uniform-transform tail. `Pass::run` returns a `PassReport` whose `warnings` flag anything that could move the public-input stream; read it. Built-in passes carry machine-checked Lean proofs (`crates/minocrab-ir/lean/`), reflected as the `VerifiedPass` marker `run_pipeline_verified` requires; cite yours with `lean_proof!`.
3. Measure: `minocrab_sim::{cost, profile}` give `(k, rows)` and a region-attributed breakdown; the calibrated primitive-cost tables (`crates/minocrab-sim/examples/`) price individual gadgets.

Good passes or circuits: publish on cargo, or open a PR if they beat the stdlib. Lean proofs of equivalence are preferred and may be merged automatically. The levers that cut gate counts are catalogued in [OPTIMIZATION.md](OPTIMIZATION.md).
