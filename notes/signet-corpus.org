#+title: sig-net Compact contracts (inventory, 2026-08-13)

GitHub org is =sig-net= (not sig-network). All repos below are public; gh auth
(DavidM-D) works for the private ones if we need them later. 20 .compact files
total across three repos.

* midnight-examples — examples/erc20-vault/contract/src/erc20-vault.compact
*The benchmark target (M6 since the 2026-08-14 reorder; was M7).*
Shielded ERC-20 vault: =initialize=, =deposit=,
=claim=, withdraw/swap request+settle circuits, schema/commitment pure
circuits. Cross-contract calls the Signet singleton; =pragma
language_version >= 0.25= → needs toolchain 0.33 (matches our pin).
The =full-stack-demo= repo is the Next.js front-end for this vault (no
.compact of its own).

* midnight-integration — packages/
- =signet-midnight/src/Signet.compact= — a *module* (library): structs,
  RequestId hashing, the SignetSigner contract interface, attestation
  verify. No circuits of its own on chain (its compiled contract-info has
  an empty circuits list). Ported as =minocrab-contracts::signet=.
- =signet-midnight/src/circuits.compact= — contract-less re-export of the
  module's pure circuits for TS unit tests; compiled with =--skip-zk=, so
  NO zkir output → nothing to differential against.
- =signet-contract/src/signet-contract.compact= — *this is the Signet
  singleton contract* the vault calls cross-contract ("the central Sig
  Network contract on Midnight", its own header). Three stateless
  emit-only circuits: signBidirectional / respond / respondBidirectional,
  each one Misc event (name pad(32,…) ‖ 256-byte payload), no ledger
  fields, no witnesses, unauthenticated by design. The 2026-08-13
  "NOT in scope" line below predates this finding — it read
  signet-contract.compact as a separate client contract; the singleton's
  circuits ARE signet-contract.compact's. Ported 2026-08-14:
  =minocrab-contracts::signet_contract=, all 3 differential-green incl.
  tamper + swapped-event-name rejection agreement
  (tests/signet_contract_differential.rs).
- =test-caller-contract{,-20-field}/src/*.compact= — cross-contract test
  callers.
- =midnight-serde/tests/fixtures/serde-fixtures.compact=

* midnight-experiments — experiments/*/contract/src/

* erc20-vault ledger-op inventory (2026-08-13, for the M4 ledger layer)
Grep of the vault: kernel.self ×11, Map .member ×9 / .lookup ×8 /
.insert ×6, Counter .increment ×5. Ledger fields: Maps (RequestId →
Bytes<32>), Counters, Cells (Bytes<20>/Bytes<32>/Uint<64>/Secp256k1Point),
sealed cells, and the struct-heavy SignBidirectionalEventMap from Signet.
So the ledger layer's priority order is: Kernel preamble + Cell + Counter
(in flight), then Map insert/lookup/member, then the event-map composite.
stdlib-wise the vault leans on secp256k1EcdsaVerify (DONE in
minocrab-std::v3), Maybe/Either, coin circuits (mint/send — need kernel
ops).
