#+DATE: 2026-11-21

* 2. What the survey found

** The core is smaller than the code around it
- There is no IR. =Builder3= (=minocrab-ir/src/v3.rs:144=) appends upstream ZKIR instructions directly and the passes rewrite raw ZKIR; notes/architecture.org still describes an L1 IR.
- The builder has no per-value definition table. =immediate_of=, =instruction_index_of= and =is_read_guarded_by= scan the whole stream backwards (=v3.rs:259,284,350=) and are called per disclosed wire, per Impact wire and per guard, so build time is quadratic (UNMEASURED).
- =Builder3= re-checks operand types at runtime and panics (=v3.rs:201-226,591-704=) although every =Circuit3= path already carries them in trait bounds; only tests reach the builder directly.
- Each pass has five or six spellings: plain fn, =_kept= fn, =Pass= struct, =ProofRef= static, =VerifiedPass= impl, =folded()=. =Kept= is checked three times. =passes.rs:1034-1328= is 295 lines of Kani specimens that say they are not proofs.
- =dedup_range_constraints= is on only in tests. No shipped circuit uses it; the gadgets avoid duplicate range checks by hand with PRECONDITION comments.
- The =unstable= feature tier is fiction: =minocrab= itself turns it on for =minocrab-ir= (=crates/minocrab/Cargo.toml:18=) and every user of sim enables it. 74 cfg sites (17 + 3 in ir, 54 in sim).
- Dead in core: =crate::Disclosure= (v2 record), =Visibility::IS_PUBLIC=, =Builder3::is_public_input=, =Selected=, the =Guarded= / =Branches= duplicate read API, =witness_guarded=, the untyped =disclose*= forms.
- =v3= naming: 487 module mentions in 171 files and 2,644 =*3= type mentions, with no v2 left.

** Std has one idea spelled eleven ways, and a layer nobody calls
- About eleven parallel per-leaf traits (=CircuitAbi=, =CircuitArg=, =CallArg=, =CallResult=, =CircuitOut=, =LedgerRepr=, =ProofWires=, =Select=, =Disclose=, =CheckOperand=, =CircuitBorsh=) all say "this value is N flat field slots". =LedgerRepr= and =ProofWires= are defined from three of the others (=ledger.rs:154-238=). Three derives exist because there is no single value trait, and the =LedgerRepr= derive rejects generics, so contracts hand-write impls.
- Five byte-string types and two integer types. =Uint= has no =add=, so contracts do =c.add= then =Uint::from_field_unchecked=: 115 unchecked constructions in contracts src. Subtraction exists three times (=Uint::sub=, =BoundedUint::sub=, =kernel::checked_sub=). Comparisons exist as free fns and methods.
- =hook.rs=, =blind.rs=, =stream.rs=, =vector.rs= (about 1,570 lines, M40-M42) have no production consumer. The one src user is =evm_flow/outbox.rs=, and =Outbox= is used only by tests. =Assumed= / =.stale(c)= exists to steer authors to hooks; contracts write =.stale(c)= about 100 times and use no hook. M44 D (rest) plans to re-base =erc20_vault_pending= on =Outbox=, so this is unfinished, not abandoned.
- App code in the general library: =#[derive(Ledger)]= finds Signet slots by matching the type names "Signet", "Pending", "Fired", "Outbox" as strings (=minocrab-macros/src/ledger.rs:104,186=); =LedgerWidth::KINDS= is Signet's response-kind check (=ledger.rs:705-750=); borsh (1,363 lines), =Serializer=, secp/EVM/base64url helpers.
- Panics the project rule wants as type errors: =from_limbs= on the point types is =unreachable!()= but =LedgerMap<_, Secp256k1Point>::lookup= compiles and reaches it (=ledger.rs:264,311,1115=); const-known runtime asserts at =vector.rs:162=, =entry.rs:862=, =v3.rs:1555,1622=.
- Nesting (=at_key=, =KeyPath=, =LedgerAdt=, =Rooted=) is used only by =nested.rs= and its test.

** How it is used

It uses the leaf types, Cell/Map/Set, the derives, =#[circuit]= / =#[contract]=, =label!= / =disclose_as=, =c.when=, the kernel. It uses none of: =Check= and the predicate layer, regions, assert messages, counters, hooks.
- It hand-rolled a preimage builder (kept after std gained one), =bytes_eq= (19 calls), cell =increment=, =either= / =implies= / =le=, a macro for P256 argument types, and its own copy of the simulator and executor.
- mpc links only =minocrab-publisher=. midnight-integration consumes checked-in ZKIR and keys. The one production contract, =signet_contract.rs=, imports six names and raw =minocrab_ledger::emit=.
- Vela (=~/dollar-app=, M47) builds on =signet_flow= / =signet_v1= / =evm_flow::Pending=. That stack is live and lives in the examples crate.
- Repeated by hand: member, assert, lookup (15 times); a private B32-equality helper in five places including std's own kernel; two assert dialects (=assert_with= 84 times in the manager, =Check.message= in the vault); =Discloses::of(())= closing 150 of 211 circuits.
- =signet.rs= (the older protocol generation) survives only because =evm.rs=, =evm_flow.rs=, =manager.rs= and the pending vault import utilities from it.

* 3. Starting points, in order

1. FIX THE GATES FIRST. Repair the nightly job and =bump.sh= gate names, make =trust_base= stop counting lines, and write down the refactor safety set above as one command. Small, and everything after leans on it.
2. DRAW THE BOUNDARY. Core = zkir, the builder, =minocrab=, ledger, std leaves/slots/kernel/entry, macros. Split =minocrab-contracts= into app library crates (=evm=, =signet=) and a corpus of parity ports and fixtures; fold the utilities out of =signet.rs= and retire it; drop the =unstable= features and the publishing scaffolding; fold interface-gen into abi. No circuit moves. Gate: every golden byte-identical.
3. TAKE THE APP OUT OF STD AND THE MACROS. Replace the name-matching in =#[derive(Ledger)]= with a trait the app crate implements; move =KINDS=, borsh, =Serializer= and the secp/EVM helpers to the app crates; move hook/blind/stream/vector and =Outbox= to their own crate until M44 D gives them a consumer. Then decide whether =Assumed= / =.stale= stays.
4. REBUILD THE BUILDER ON A DEFINITION TABLE: per value, its type, defining instruction and known constant. Removes the linear scans and the runtime type asserts, and gives constant knowledge to everything above. Gate: byte-identical.
5. REDUCE PASSES TO FILTER FUNCTIONS, THEN ADD ONE SIMPLIFICATION PASS. Delete the =Pass= / =VerifiedPass= / =ProofRef= scaffolding and the Kani specimens; turn range dedup on or delete it; add constant-operand simplification and pure-op CSE. This is where rows come from. Measure first. Gate: =row_snapshot= flat or down, differentials under the same normalisation on both sides.
6. ONE VALUE TRAIT IN STD. Collapse the per-leaf trait tower into a single flat-value trait with blanket impls and one derive that accepts generics. The largest abstraction win and the riskiest step, since slot order is the wire contract. Gate: goldens, interface snapshot, rows.
7. ONE INTEGER, FEWER BYTE TYPES, AND THE PRIMITIVES AUTHORS KEEP WRITING. =Uint= with checked arithmetic so the 115 unchecked constructions go; B32 equality as a check; =lookup_required=; cell increment; default self-address caching; one assert style. Turn the point-cell panic and the const-known asserts into compile errors.
8. MOVE THE TAINT LINT TO ITS OWN CRATE and the disclosure policy next to the macros. Pure moves.
9. TESTS, FOLLOWING THE CODE. Share the ops/canonical/corpus helpers; shrink the generated snapshots to their real checks; delete the A-equals-B tests with the APIs they compare.
10. LAST: rename =v3= to the crate root and drop the =3= suffixes in one mechanical commit; strip milestone narration from comments; collapse the top-level docs.

* 4. Rulings (dmd, 2026-11-21)

- COMPAT CRATE: anything that exists to keep the emitted stream byte-for-byte equal to compactc's goes in a compat crate, labelled with why it exists. It is kept, not deleted.
- KEEP: everything that limits what type-checks (nothing that enforces safety is removed); unlabelled disclosures; unchecked integer construction.
- CROSS-CONTRACT CALLS are not experimental now ledger 9 is out (update =~/compact= to see it). =contract_call=, =#[interface]=, abi and the interface crates are core-adjacent, not parked.
- EXPERIMENTAL CRATE: raw Impact written by a contract author, and things like it, as far as possible. The =impact_mixed= primitive stays in core because the slots lower to it.
- Do not remove anything that makes the Sig demos read better.
- This supersedes the parts of section 3 that delete the untyped =disclose*= forms (step 4's dead-item list), that make checked arithmetic the only path (step 7), and that make the simplifications unconditional (steps 5 and 7).

* 5. Rulings, second round (dmd, 2026-11-21)

- DEPLOYED ARTIFACTS DO NOT MOVE. The signer and every circuit with a Compact twin stay byte-identical; only MinoCrab-only contracts (Vela, the pending vault, passport) get the optimised stream.
- COMPAT IS GADGETS WHERE POSSIBLE: the compactc-shaped variant of a gadget lives in the compat crate and the parity ports import it. A build-wide switch only where a gadget cannot carry it.
- RUNTIME CHECKS: keep one runtime backstop per invariant, drop the duplicates of it.
- HOOKS, BLIND OPS, STREAM, VECTOR, OUTBOX STAY IN STD.
- THE SIG DEMOS are the erc20 vaults (=erc20_vault=, =erc20_vault_pending=) and what they read from; =Pending=, =signet_flow=, =signet_v1=, =evm_flow= stay.
- THE PUBLISHER stays in this repo, untouched by the cleanup.
- THE =v3= RENAME goes last, one commit. Nothing is published, so breaking imports is acceptable; a re-export shim is kept for the downstream pins.
- Not answered, running on the defaults offered: keep =lean_proof!= and the proof references, delete the Kani specimens that say they are not proofs; work in a worktree off =main= (=~/minocrab-streamline=, branch =streamline=).
- AFTER THE CLEANUP: the examples move to the erc20 vaults and Sig SDK versions pinned for mainnet.
- THEN PUBLISH READINESS (same day). This reverses the survey's suggestion to drop the publishing scaffolding: it stays, and new crates (compat, experimental, the app crates) are created publishable from the start.
- THE EVM AND SIGNET APP CRATES ARE PUBLISHED. So they may not depend on =minocrab-contracts= (the unpublished corpus), their tests may not need the corpus to build, and anything they share with the old =signet.rs= generation has to live in a published crate.

* 7. The compat crate, as decided from the inventory (2026-11-21)

=minocrab-compat= depends on std, ledger, =minocrab= and ir; nothing depends on it except the parity ports and their tests. Its crate docs carry the label: it exists so that a circuit ported from Compact emits compactc's instruction stream byte for byte, which is how a port is checked against the compiler's own output, and nothing in it is the cheapest correct lowering.

** What goes in it
| module | what | why it is compactc-shaped |
|--------+------+---------------------------|
| =kernel= | the Compact standard-library transcription now at std =kernel.rs:324-809=: send / mint / receive unshielded, the negated balance and block-time forms, =merge_coin=, =send_shielded=, =checked_sub=, =as_uint128= | =not= as =cond_select(b,0,1)=; =&&= as =cond_select=; the guard conjoined once per op; =send_shielded= hashing one coin commitment twice (about 5,640 rows a use) |
| =merkle= | =insert_index_default= with the unfolded default leaf hash | compactc does not fold =persistentHash= over constants (one SHA block, about 1,885 rows) |
| =secp= | =secp256k1_ecdsa_verify= as compactc lowers it | the identity point built by =ec_mul_generator= + two conversions (about 12,300 rows for a constant) and an x-coordinate round trip |
| =normalise= | =folded()= | the normaliser the eight instruction-level differentials apply to both sides |
| =profile= | one call a parity circuit makes first | see the switch below |

** The one switch
Three things cannot be a gadget, because shared helpers (=common.rs='s mint, burn and receive, used by both vaults) call core: whether =kernel::self_address= reads fresh at every call or once per circuit; whether repeated range constraints are deduplicated; whether the simplification pass runs. Core holds these as per-circuit lowering state, defaulting to the lean choice. =minocrab_compat::profile(c)= sets all three to compactc's. Every circuit with a Compact twin, and the deployed signer, calls it first; the gate that it was applied everywhere it must be is the zkir dump staying byte-identical.

** Order
1. COPY, do not move: the compat crate gets the compactc-shaped gadgets, the parity ports import them, std is unchanged. Zero movement.
2. The lowering state and =profile=, with the defaults still compactc's. Zero movement.
3. Flip each default and make each std gadget lean, one at a time. A parity port must not move at all; a MinoCrab-only circuit may only go down in rows; each lean gadget gets a test that it is public-input-equal to its compat twin on the same inputs.

** Stays in core although it looks like compat
- The Impact op sequences, the protocol hash preimages, the input-constraint table and alignment widths, guarded-effect semantics: the ledger and the VM require them.
- =fold_immediate_copies=: zero rows, and nothing gains from a second shape.
- Uncached =idx= opcodes (56 sites in =minocrab-ledger=): the cached form is valid and cheaper in gas, but the op builders are pure functions and a switch would thread through all of them. DEFERRED, recorded here.
- =Callee::Field='s fresh read per call site: the lean form, =.pin(c)=, already exists.
- =Check::or= is NOT compactc's shape (compactc lowers =||= to one =cond_select=); it is simply expensive. Core makes it one =cond_select=. Its only caller is =evm_flow.rs:1452=.

* 8. The value traits, as designed (2026-11-21, rung G, not started)

** What is there
Every leaf and record type answers the same three questions through differently named traits. Its static layout: =CircuitAbi= (=SLOTS=, atoms, prims). Its encoding to field slots: =CallArg::push_call_slots= at =Public=, =CircuitArg::push_slots= at =Private=, =LedgerRepr::push_limbs= at =Public= with the circuit in hand, =ProofWires::push_wires= for the bare values. Its decoding from slots: =CallResult::from_call_slots=, =LedgerRepr::from_limbs=, and =CircuitArg::declare= for a fresh argument. =LedgerRepr= and =ProofWires= are generated from the call traits by a macro for fourteen leaf types (=ledger.rs:124-176=), and contracts hand-write ten =LedgerRepr= and ten =ProofWires= impls because the derive rejects generics.

** What replaces it
- =CircuitAbi= stays: it is the layout.
- =Encode<V>=: one method, the value's slots at visibility =V=. =CallArg= becomes =Encode<Public>=; =CircuitArg::push_slots= becomes =Encode<Private>=.
- =Decode<V>=: one method, the value from its slots. =CallResult= becomes =Decode<Public>=.
- The ledger pair is SPLIT, not merged: =LedgerWrite= (atoms and limbs; blanket over =Encode<Public>=, hand-written for the two point types, whose limbs come out of the =encode= gate) and =LedgerRead: LedgerWrite= (=from_limbs=, =witness_read=; blanket over =Decode<Public>=). The point types implement only =LedgerWrite=. =LedgerMap::lookup= and every other method that rebuilds a value asks for =LedgerRead=, so a map of points that is looked up stops compiling with a missing impl; today it compiles and reaches an =unreachable!()= (=ledger.rs:264,311=). Insert and member on such a map keep working. This ADDS a type restriction and removes a panic.
- =ProofWires=: blanket over =Encode<Public>=, kept by hand for the points and the bare wire.
- =CircuitArg= keeps =declare= and =constrain=: argument names come from field paths and a point argument is not flat slots, so it is not a decode.
- ONE DERIVE produces =CircuitAbi=, =Encode= and =Decode= for a record, generic parameters allowed; the ledger and proof-wire impls then come from the blankets, and the hand-written ones in contracts go.

** What must not move
Slot order is the wire contract. Gates: the 227-circuit dump identical, =interface_snapshot= unchanged, =row_snapshot= unchanged. The old trait names stay as aliases or supertraits for one step if that keeps the passport port compiling; say which in the commit.

** Order
1. Introduce =Encode= / =Decode= and re-express the leaf table through them; old traits become blanket impls. No call site changes.
2. Split =LedgerRepr=; bound the rebuilding methods on =LedgerRead=; a =compile_fail= doctest for the looked-up point map.
3. The one derive; delete the hand-written impls in contracts.
4. Remove the old names once nothing in the workspace uses them.
