* B, the one-spelling audit: conditionals (2026-09-05, dmd's ask)
dmd: "can we do a `when`, then do the guard using the inner c?" — and,
once the `when` variants were laid out, "weed out any other way of doing
things conditionally (provided … it doesn't remove expressivity)".

FINDING. The eDSL spelled a conditional read four ways: the scope
(`c.when(g, |c| …)`), the per-operation guard parameter (`_under`: 40
methods in minocrab-std, returning the value bare), the per-operation
guard parameter with a `Guarded` return (`_guarded`: 28 methods in
std + 5 raw `_guarded[_at]` in minocrab-ledger), and the in-branch
assert `c.assert(p.when(g))` on `Check`. The raw ledger layer threads
an explicit `guard: impl Into<Operand>` through 36 functions
(`STRAIGHT_LINE` at 97 call sites). All four lower identically: the
effect layer conjoins the ambient scope with any explicit guard
(`effect_guard`), an immediate-1 explicit guard yields to the ambient
(`Imm 1` ≡ `None` at `emit_impact` and `read_guard`), and nesting
conjoins once on entry — so the scope IS the threaded form, byte for
byte (v3_guard_scope pins every shape). Callers of the threaded forms
in the contracts: 7 (3 `lookup_guarded`, 2 `own_public_key_guarded`,
`self_address_under`, `self_address_guarded`).

WHAT WAS MISSING for the scope to be the only spelling: a way to carry a
READ out of a `when` body with its guard attached and zero instructions.
`when_value(..).otherwise(..)` selects (one `cond_select` per slot) and
is exhaustive by construction — right for "the value of the arm that
matched", wrong for "the read, default where skipped".

DONE (6e1ee5d): `when` / `when_private` bodies return `R`; `Branches<V,
R>` carries it and ends with `.or_default()` (zero instructions),
`.or(fallback)` (one select per slot), `.assert_read()` (assert the
guard) or `.guarded()` (hand on a `Guarded`). `else_when` / `otherwise`
stay on `Branches<V, ()>`, so a value-carrying chain cannot grow arms
(type error). A private chain's arms are private scopes (the on-chain
refusal holds in `otherwise`; pinned). `Bool<V>: GuardCond`, so a
`when` takes the boolean rather than `.field()`. Zero movement: the
209-circuit dump is byte-identical.

THE THREE THAT REMAIN and why each: `when` — public condition, effects
allowed, value or unit; `when_value` — the if-expression, every arm a
value, `otherwise` mandatory, selects; `when_private` — private
condition, on-chain emitters refuse at build time (the one rejection
that is a panic, not a type error: the scope stack is dynamic —
notes/contract-api.org panic registry entry 5; a type-state `Circuit3`
is the M26 authoring-path item on dmd's hold).

MISUSE SURFACE, checked: a private guard on `when` → compile error
(`OnChainGuard`); a value dropped from a `when_value` chain → must_use
warning (`Selected`, `ValueBranches`); a `Guarded` dropped → must_use;
an `else_when` after a value body → type error; a witness inside any
scope picks up the guard (semantic, pinned); a non-boolean guard wire →
UNSATISFIABLE, not silent (the reference circuit converts every Impact
and read guard to an assigned bit under an equality constraint —
midnight-circuits 7.2.4 native_chip.rs `convert`). Not a warning: a
value returned from a `when` body and never taken (`c.when(g, |c|
map.lookup(c, k));`) compiles silently, as any discarded expression
does; the read's effect is still emitted.

NEXT (the removal, delegated with the dump gate): every `_under` /
`_guarded` method in minocrab-std (ledger.rs, v3.rs, kernel.rs), the
raw `_guarded[_at]` reads and `kernel_self_guarded` in minocrab-ledger,
the explicit `guard` parameter on the 36 raw ledger functions and
`STRAIGHT_LINE`, `Check::when(guard)`, `mint_read_with`'s guard, and
`Guarded::new` made crate-private; the 7 contract call sites and the
tests rewritten to the scope. KEPT: `Circuit3::impact` /
`impact_mixed` / `witness_guarded` / `public_transcript_input_guarded`
in the core crate — the primitives the scope lowers to, and the twins
the byte-identity tests compare against; documented as such, not for
contract code. This is a public-API removal on minocrab-std, which §B's
"public signatures on the stable tier do not change" did not
anticipate; dmd asked for it explicitly.

** THE ZERO-MOVEMENT SURPRISE, recorded for the design record

The scope conjoins ambient-and-explicit ONCE, on scope entry
(`Circuit3::push_guard`). The deleted `_guarded` primitives conjoined it
ONCE PER EFFECT (`Circuit3::effect_guard`, called fresh by every read and
every Impact op). The two are byte-identical ONLY when there is no outer
ambient scope at the call site (the straight-line case the design doc's
byte-identity claim was built on) — nest an explicit `_guarded` call inside
another `c.when` and replacing it with a new inner `c.when` removes the
redundant per-effect selects, which is a real row reduction, not a
refactor. Found by the zero-movement gate itself: `manager__execute.zkir`
and `manager__deposit_shielded.zkir` first came back with fewer
`cond_select`s after the naive `c.when` conversion. Fixed by reproducing
the deleted primitives' exact instruction sequence through the KEPT core
primitives at the three call sites that nest (`guarded_kernel_self`,
`emit_guarded` in `minocrab-std/src/v3/kernel.rs`;
`guarded_map_lookup_field` in `minocrab-contracts/src/manager.rs`) instead
of routing them through the scope. Every OTHER `_guarded`-to-scope
conversion in this removal is called straight-line only (verified: the
205-circuit... — see gate output — dump stayed byte-identical), so this
is the only place it bites in the current corpus.

The same "wire numbering" trap: `c.constant(1u64)` compiles to zero rows
regardless of whether it is read afterward (`minocrab_ir::v3::passes::
fold_immediate_copies` drops every named-immediate `Copy` that is not a
circuit output), but the IDENTIFIER counter that names later wires
(`Builder3::fresh`) increments when the `Copy` is EMITTED, before the fold
runs — so deleting a now-guard-only `let one = c.constant(1u64);` silently
renumbers every wire after it in the dump, even though the row count does
not change. Every such declaration this removal made guard-unnecessary is
kept in place (`let _ = c.constant(1u64);`, one-line comment) rather than
deleted, across `attest.rs`, `erc20_vault.rs` (×3), `events.rs`,
`events_borsh.rs`, `hashing.rs` (×2), `manager.rs` (×2),
`signet_contract.rs`, `signet_flow.rs`, `test_caller.rs`, `xcall.rs`
(×6), `xcall_with_payment.rs` (×5), `xcontract_events.rs` (×2),
`xcontract_events_borsh.rs` — 27 sites total, one per circuit the initial
(wrong) deletion moved.

** WHAT COULD NOT BE REMOVED, and why

Nothing on dmd's list survived. The four core-crate primitives
(`Circuit3::impact`, `impact_mixed`, `witness_guarded`,
`public_transcript_input_guarded`) are KEPT BY DESIGN — they are what the
scope lowers to, not a second spelling contract code should reach for
(now documented as such at each). Three private helpers earn their keep
for the same reason at nested call sites where the scope's once-on-entry
conjoining would move rows: `guarded_kernel_self` and `emit_guarded`
(`minocrab-std/src/v3/kernel.rs`), `guarded_map_lookup_field`
(`minocrab-contracts/src/manager.rs`). All three are private, undocumented
outside this crate's internals, and exist ONLY because their one caller
each nests under another scope — everywhere else in the corpus the plain
method under `c.when` is the whole story.
