Ad-hoc, on dmd's work order: add

Not a planned milestone; recorded here because the port surfaced a real

* What it is
An account-abstraction custody contract: dual-mode authorization (a
Midnight witness secret, OR an Ethereum EOA signing EIP-712),
family-separated shielded/unshielded custody, and ONE write gateway
=execute= over seven selectors (register native/EVM, withdraw
shielded/unshielded, internal transfer shielded/unshielded, open swap).
It calls NO other contract — it reimplements EIP-712 + ECDSA and custodies
zswap coins directly (unlike the erc20-vault, which offloads to the Signet
singleton). Pinned in corpus/sources.json; artifacts under
corpus/zkir/aa-midnight-evm-experiment/. Now 315 corpus artifacts (312 →
315; the entry_point sweep's frozen count moved and was accepted).

* The port is SEMANTIC, not instruction-mirroring
The ledger-op stream (the PI contract) reproduces compactc's exactly, read
off the compiled vm-code (contract/index.js) function by function; the
in-circuit arithmetic uses OUR lowerings — the keccak chip's in-chip byte
packing where compactc splices Bytes<N> byte by byte, div_mod shifts for
the big-endian ABI words, guarded reads whose =or_default()= IS compactc's
read-as-zero with no select. Equivalence is M3's criterion (same typed I/O
schema + equal pis/pi_skips on a shared preimage), in
crates/minocrab-contracts/tests/manager_differential.rs — 20 scenarios
(native+EVM registration, both transfer families, both withdraw families,
open + named/exact-spend swaps, guard-rejection agreement).

* THE CORE BUG the port exposed, and its fix
=Circuit3::public_transcript_input_guarded= did NOT resolve its explicit
guard against the AMBIENT scope, while an emitted op's guard always does
(through =resolve_guard=). So a =_guarded= transcript read inside a
=when()= branch fired its PI gates on the raw guard while its op embed
stayed skipped under the conjunction — shifting every LATER read's public
inputs. First hit by =sendUnshielded='s auto-receive =kernel.self= read
inside =custodyDispatch='s =isWithdrawUnshielded= arm, which a named-swap
call reaches with =is_left= true while the arm is off.
FIX (crates/minocrab/src/v3.rs): route the guard through =resolve_guard=,
same as an op. VERIFIED ZERO-MOVEMENT: all 200 pre-existing circuits'
serialized ZKIR byte-identical with and without the fix — which also
PROVES no existing circuit had a =_guarded= transcript read under an
ambient guard where the conjunction mattered (else its dump would have
moved), so the existing corpus was never affected; the manager was the
first to reach the case.
REGRESSION TEST: =a_guarded_read_inside_a_scope_conjoins_both_guards= in
minocrab-std/tests/v3_guard_scope.rs, confirmed to FAIL without the fix
and pass with it.
