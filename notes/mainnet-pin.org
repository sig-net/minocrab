* 6. Downstream

** API breaks in the published crates (old → new, why)
- =signet_signer_interface= 0.3.0 → 0.4.0: =Signature=, =AffinePoint=, =SignatureRespondedEventV1=, =RespondBidirectionalEventV1=, =SignetSigner::respond=, =SignetSigner::respond_bidirectional=, =SignetSigner::RESPOND= / =RESPOND_BIDIRECTIONAL= are GONE (they are the responder's, =signet_responder_interface::{…, SignetResponder}= 0.1.0). =RequestId=, =SignBidirectionalEventNotification=, =SignetSigner::sign_bidirectional=, =notification::construct_notification_v1= are unchanged.
- =minocrab_signet::signet_v1= (and =minocrab_contracts::signet_v1=), the protocol move to rc.15:
  - =SignBidirectionalEventV1::execution_dest: Caip2Id<V>= → =ExecutionDest<V>= (=BytesN<V, 64>=); likewise =RequestIdPreimageV1::execution_dest= and the =execution_dest= parameter of =construct_sign_bidirectional_event_v1{,_const_path}=. =ethereum_caip2_id::<V>(c) -> Caip2Id<V>= → =-> ExecutionDest<V>=. =layout::signature_dest(words)= and everything after it moves by one limb (=layout::limbs(2, 2)= 30 → 31). Why: =executionDest= is =Bytes<64>= in the module since 0.25.
  - =RespondBidirectionalEventV1<V>= gains =output_hash: B32<V>= between =serialized_output_length= and =digest=; its =signature= is now =signet_responder_interface::Signature<V>=. Why: the attestation carries the output's hash since 0.25.
  - =calculate_attestation_digest_v1::<V, LEN>(c, id, height, kind, &output_limbs)= → =calculate_attestation_digest_v1::<V>(c, id, height, kind, serialized_output_length, &output_hash)=; =calculate_attestation_digest_v1_at= and =attestation_transient_hash_v1= are REMOVED; =verify_respond_bidirectional_event_v1::<V, LEN>= is REMOVED (=verify_respond_bidirectional_event_v1_at(c, len, &limbs, &event, key)= keeps its signature). NEW: =calculate_attested_output_hash_v1=, =verify_respond_bidirectional_attestation_v1(c, &event, key)=, =verify_attested_output_v1::<V, LEN>= / =verify_attested_output_v1_at=, =hash_domain::ATTESTED_OUTPUT=, =EXECUTION_DEST_LEN=. Why: the digest is over the output's width and hash.
- =minocrab_signet::evm_flow= (=minocrab_contracts::evm_flow=): no Rust signature changed. =Pending::complete= / =refund= / the =Succeeded= / =Failed= tickets keep their types; the tickets' =respond= field is the new struct, so every settle circuit takes two more input slots, and its ZKIR and verifier key move.
- =minocrab_contracts::signet_contract::SignetContract= → =Signer= (=sign_bidirectional=) and =Responder= (=respond=, =respond_bidirectional=).
- =minocrab_contracts::erc20_vault=: =queue_attestation0/1/32= → =queue_attestation=; =initialise= takes twelve arguments, =add_allowed_token= two; NEW =set_token_fees=, =set_fee_recipient=, =TokenFees=, =AllowedTokenConfig=, =TokenFeesArg=, =FEE_MINT_PAD=; =AttestationRecord= fields; the four args structs gain =fee=; =DEFAULT_WITHDRAW_GAS= / =DEFAULT_APPROVE_GAS= 100000 → 200000.
- =signet-sim= (unpublished, used by Vela's devnet): =AttestationV1= gains =output_hash=; =hashing::v1::attestation_digest= returns =(output_hash, digest)=; =hashing::v1::ethereum_caip2_id() -> [u8; 64]=; =hashing::v1::request_id= takes a 64-byte =execution_dest=; =records::SignBidirectionalRecordV1::execution_dest: [u8; 64]=.
- =minocrab-publisher=: NO API change. Its calls are per circuit against a caller-built =Deployment=; a =respond= / =respondBidirectional= is now built against the RESPONDER's address with =ManagedDir::deployment(responder_address, signet_artifacts::RESPONDER_CIRCUITS)=, a =signBidirectional= against the signer's.

** The external MPC node
It links =minocrab-publisher= by a pinned git revision, so it is unaffected until it moves that pin. When it does: (1) post respond calls to the responder's address, not the signer's, and build their =Deployment= from the respond pair only (=check_deployed= against the responder's contract state; the three verifier-key hashes are unchanged, =respond= =15954f57…=, =respondBidirectional= =9778599e…=); (2) nothing in =signet-protocol= or =signet-hashing= changed on the wire (the event names, the 288-byte Misc payloads, the request id, the attested output hash and the attestation digest are all v0.25.0's), so its readers and its =decode_misc= use need no change; (3) a client record it reads now has a 64-byte =executionDest=, which =signet_hashing::SignBidirectionalRecord= has carried since M45 G; (4) if it also links =signet-signer-interface= anywhere for the response types, they moved to =signet-responder-interface=.
