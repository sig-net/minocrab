* Still open, ranked — candidates for milestones / bug fixes

** 1. §4.1 HIGH — private guard bits drive public effects, manifest-blind
Confirmed unchanged: =when<V: Visibility>= (v3.rs:1468), =impact<V>=
(1331), =impact_mixed<V>= (1351) and every =_under= accept any V. No
=DisclosureKind::Guard= exists (lib.rs:175). No note anywhere discusses
guard visibility — this is a genuinely new finding, not a refused one.
A guarded Impact op's presence is on-chain, so =c.when(secret_bit, ..)=
publishes the bit with no =disclose= and no manifest entry.
Proposed: (i) SURVEY FIRST — count the sites in the corpus where the
effective guard of an Impact op / transcript read is Private; that number
decides the fix. (ii) Preferred fix per the hard rule: a =Public= bound on
the guard of every EFFECTFUL operation (=impact=, =impact_mixed=, =emit=,
the ledger =_under= family, and =when= when its body emits — the last is
the hard one, since =when= cannot see its body; the practical spelling is
the Public bound on the emitters, so a private =when= over a body that
emits fails at the emitter with an on_unimplemented message telling the
author to =disclose= the condition). Pure assertions/witness reads under a
private guard stay legal (no on-chain effect). (iii) Fallback:
=DisclosureKind::Guard= recorded on every guarded emit whose guard is
Private, so the =Discloses<>= set-equality test sees it. CHECKED
2026-08-27 with the pinned compactc (0.33.0-rc.2): it REJECTS the
program. `if (c) { x = ...; }` with `c: Boolean` a circuit parameter
fails to compile — "performing this ledger operation might disclose the
boolean value of the witness value via this path through the program:
the conditional branch at line 8" — and compiles once the condition is
spelled `if (disclose(c))`. So §4.1 is not a judgement call: Compact's
own disclosure rule is that a witness-derived branch condition guarding
a ledger operation IS a disclosure, and our accepting it silently is a
divergence from compactc (api-safety-survey §0(b)). The fix should
reproduce that rule at the type level: a public (disclosed) guard on
every on-chain effect.

** 2. §4.2 MEDIUM — three assert entry points bypass the ambient guard
Confirmed unchanged: =assert= goes through =assert_with= →
=self.ambient()= (v3.rs:1234); =assert_eq= (1244), =assert_bits= (1252),
=assert_boolean= (1256) call the builder directly. VERIFICATION.md:197
still claims "the ambient guard reaches reads, witnesses and assertions".
Borsh tag checks use =c.assert_eq= (borsh.rs:442, :542); 7 call sites in
std/ledger/contracts. Fails closed (unprovable, not a leak).
Proposed: route all three through the guard — =assert_eq(a,b)= ↦
=constrain_eq(select(g, a, b), b)=, =assert_bits(w,n)= ↦
=constrain_bits(select(g, w, 0), n)=, =assert_boolean= likewise — with
no ambient guard the path is unchanged (zero movement on every straight-
line circuit; the dump instrument proves it). Add three tests to
v3_guard_scope.rs. Correct VERIFICATION.md:197 either way.

** 3. §4.3 MEDIUM — the other half: =witness_guarded= is still verbatim
=witness_guarded= (v3.rs:859) passes =Some(Arg::Val(guard.val))= straight
through; =public_transcript_input_guarded= (892) now calls =resolve_guard=.
So the =_guarded= family is now inconsistent WITH ITSELF, and
=own_public_key_guarded= (std v3.rs:2197) inherits the verbatim regime.
Inside a =when=, a =_guarded= witness consumes the private transcript
when =inner && !outer=, desynchronising every later witness — the exact
class =da794c5= fixed for the public side, invisible to honest-preimage
differentials. Two callers in std/ledger.
Proposed: one-line fix (=resolve_guard= in =witness_guarded=), a mirror
regression test, dump-gated (expect zero movement — no corpus circuit
runs a =_guarded= witness under a scope, or da794c5's sweep would have
seen it). Also record: =contract_call= (ledger lib.rs:2403) reads its
callee witnesses with ambient-only =c.witness= and emits with the explicit
guard, and no corpus circuit exercises a non-trivial guard on a call —
whether =contract_call(c, g=false, ..)= at top level should consume the
callee's witnesses is unverified against compactc.

** AS BUILT — items 2 and 3, one commit (review-fixes, 2026-08-27)
The two findings were the same bug: the guard was consulted method by
method, and the review found the cells of that table that were wrong.
Fixed structurally rather than cell by cell — =minocrab/src/v3/effects.rs=:
- =EffectGuard=, a private-field type only =Circuit3::effect_guard=
  constructs; it is the ONLY reader of the guard stack (scope push/pop
  moved there too). Every raw emitter (=private_input=, =public_input=,
  =impact=, =assert=, =constrain_eq=, =constrain_bits=,
  =constrain_to_boolean=) is reachable only through an =emit_*= that takes
  one. A unit test pins that =v3.rs= contains no raw emitter call and no
  =self.guards.= access, so the surface has no spelling for "emit an
  effect under a guard that skipped the scope".
- Semantics, all compactc's: reads and Impact carry the guard as an
  operand; =assert= is =assert(select(g, x, 1))=; =assert_eq= in a scope is
  =test_eq= + guarded assert (compactc's =assert(a == b)= in a branch);
  =assert_bits= / =assert_boolean= check =select(g, w, 0)=. Straight-line
  code is untouched (no ambient ⇒ the direct instruction).
- ONE EXEMPTION, compactc's own: a range check on a transcript read that
  carries THIS guard needs no select (the read is 0 where the guard is
  off — =Builder3::is_read_guarded_by=). Without it the port lineage's
  =own_public_key= reads inside =c.when= gained a select compactc does
  not emit (5 vault circuits moved); with it, byte-identical.
- Verified against compactc directly: a cast inside =if= lowers as
  =select(c, value, 0)= then a guarded check — the value zeroed on the
  untaken path, the check holding trivially. That is the shape emitted.
- A side fix the choke point made visible: =assert_with='s message was
  recorded at the index BEFORE the scope's select, so every named assert
  inside a =when= pointed one instruction early and the simulator could
  not find it. Now recorded at the =Assert= itself; test pins it.
- Movement, declared: 2 of 209 circuits. =manager::deposit_shielded=
  +1 =cond_select= (+1 row, 38487→38488) and =manager::execute= +4
  (+4 rows, 209330→209334), one per scoped 128-bit check:
  =merge_coin_immediate='s constraint on =pooled.value + coin.value=
  inside =c.when(member)= (and execute's per-arm twins) now holds on the
  path not taken. The manager is PI-anchored (no compactc stream to
  match); k unchanged; rows re-frozen with this as the reason. All other
  207 byte-identical (zkir dump, before/after).
- THE TAINT LINT CAUGHT THE FIRST DRAFT. With the guarded check spelled
  =constrain_bits(select(g, sum, 0))= and the merged coin's value still
  =sum= downstream, the coin-commitment hash consumed a limb the lint
  could no longer prove bounded (two NEW findings, one per manager
  circuit). The draft was wrong and the lint was right: on the path not
  taken =sum= IS unbounded. The fix is compactc's semantics — a value
  checked inside a branch IS the selected value — so =assert_bits= /
  =assert_boolean= / =LimbConstraint::emit= now RETURN the wire they
  constrained, =constrain_input= returns the constrained =Self=, and
  =from_field_checked= / =as_uint128= carry it forward. The hash then
  consumes the bounded =sel=; zero new findings. The manager circuits'
  remaining baseline diff is pure re-indexing (their instruction numbers
  shifted by the added selects), verified by a normalised comparison
  (indices and wire numbers stripped: 329 → 329, nothing new, nothing
  gone).
- Tests: 5 new in =v3_guard_scope.rs= (26 total), the choke-point pin in
  =effects.rs=. VERIFICATION.md's guard-scoping row restated.
- NOT done here: the two guard REGIMES still coexist (=_guarded= /
  =_under= explicit vs =when= ambient). They now compose correctly, which
  was the bug; whether the explicit family should become =pub(crate)= is
  a separate API decision.

** 4. §3.5 + §4.5 — the disclosure manifest is opt-in, and a set
Confirmed: the macro pins =a_circuit_without_a_declaration_gets_no_test=
(circuit.rs:648); =disclosed_labels= is a =BTreeSet<&str>= (disclose.rs),
so duplicate labels collapse and a free-string =c.disclose(w, "L")= can
satisfy a declared =L=.
Proposed, zero API change: every =#[circuit]= WITHOUT a =Discloses<>=
return gets a generated test asserting =disclosed_labels()= is EMPTY —
"returns ()" then means "declares nothing", and a =c.disclose= in such a
circuit fails its own test. Make the comparison reject duplicate labels
(a =Vec= compared as a multiset, or an assert on =len()=). The
=#[cfg(test)]= point (a crate shipped without running tests never checks)
is the CI item and stays out of scope.
