** 1. §4.1 HIGH — private guard bits drive public effects, manifest-blind
Confirmed unchanged: =when<V: Visibility>= (v3.rs:1468), =impact<V>=
(1331), =impact_mixed<V>= (1351) and every =_under= accept any V. No
=DisclosureKind::Guard= exists (lib.rs:175). No note anywhere discusses
guard visibility — this is a genuinely new finding, not a refused one.
A guarded Impact op's presence is on-chain, so =c.when(secret_bit, ..)=
publishes the bit with no =disclose= and no manifest entry.
Proposed: (i) SURVEY FIRST — count the sites in the corpus where the
effective guard of an Impact op / transcript read is Private; that number
decides the fix. (ii) Preferred fix per the hard rule: a =Public= bound on
the guard of every EFFECTFUL operation (=impact=, =impact_mixed=, =emit=,
the ledger =_under= family, and =when= when its body emits — the last is
the hard one, since =when= cannot see its body; the practical spelling is
the Public bound on the emitters, so a private =when= over a body that
emits fails at the emitter with an on_unimplemented message telling the
author to =disclose= the condition). Pure assertions/witness reads under a
private guard stay legal (no on-chain effect). (iii) Fallback:
=DisclosureKind::Guard= recorded on every guarded emit whose guard is
Private, so the =Discloses<>= set-equality test sees it. CHECKED
2026-08-27 with the pinned compactc (0.33.0-rc.2): it REJECTS the
program. `if (c) { x = ...; }` with `c: Boolean` a circuit parameter
fails to compile — "performing this ledger operation might disclose the
boolean value of the witness value via this path through the program:
the conditional branch at line 8" — and compiles once the condition is
spelled `if (disclose(c))`. So §4.1 is not a judgement call: Compact's
own disclosure rule is that a witness-derived branch condition guarding
a ledger operation IS a disclosure, and our accepting it silently is a
divergence from compactc (api-safety-survey §0(b)). The fix should
reproduce that rule at the type level: a public (disclosed) guard on
every on-chain effect.

** AS BUILT — item 1 (review-fixes, 2026-08-28)
=minocrab::OnChainGuard=: a sealed marker on the one visibility that may
guard an on-chain effect (=Public=), with an =on_unimplemented= that
names the fix. Bounded at the three choke-point entries — =when= /
=when_value= (the scope), =impact= / =impact_mixed= (the op),
=public_transcript_input_guarded= (the read) — and carried by the
compiler through every generic forwarder: 134 signatures across 7 files
— 50 in the ledger (=emit=, the =_under= family), 68 in the stdlib
(=ledger.rs=, =kernel.rs=), 4 in =contracts/common.rs=, 2 in the
=#[interface]= macro's generated methods, 5 hand-written forwarders in
=tests/interface_macro.rs=, and the 5 core entries. Each is a =+ OnChainGuard= on the guard's
visibility parameter, placed where rustc pointed (a scripted loop, so
the sweep is exactly the compiler's closure, no more). =witness_guarded=
keeps any visibility — consuming the private transcript is not visible.
- Zero library meaning changed: a probe restricting the bound found
  callers only in tests (no circuit in the workspace guards an on-chain
  effect on a private value). The tests that used raw =arg= wires as
  guards disclose them first; =c.disclose= is a record, not an
  instruction, so every byte-identity assertion in =v3_guard_scope.rs=
  still holds unchanged.
- One API gap the bound exposed, closed: a =when_value= over PRIVATE
  values under a (now necessarily public) condition needs
  =Select<Public>= for the private leaves — added for =Wire3=, =Bool=,
  =Uint=, =Bytes=, =B32=, =ContractAddress=, =UserAddress=, =Maybe=,
  each delegating to the leaf's =Select<Private>= with the bit demoted
  (same =cond_select=). The other mixed case — a private bit over public
  values — is deliberately absent: the result would reveal the bit.
- NOT provided: a private-condition scope for bodies with no on-chain
  effect (assert / witness only). Compact allows it; nothing here uses
  it; the API stays small. The shape if needed: =when_private(cond,
  body)= with any visibility, on-chain emitters failing at build time
  inside it (the ladder's last rung, since the scope stack is dynamic).

** 2. §4.2 MEDIUM — three assert entry points bypass the ambient guard
Confirmed unchanged: =assert= goes through =assert_with= →
=self.ambient()= (v3.rs:1234); =assert_eq= (1244), =assert_bits= (1252),
=assert_boolean= (1256) call the builder directly. VERIFICATION.md:197
still claims "the ambient guard reaches reads, witnesses and assertions".
Borsh tag checks use =c.assert_eq= (borsh.rs:442, :542); 7 call sites in
std/ledger/contracts. Fails closed (unprovable, not a leak).
Proposed: route all three through the guard — =assert_eq(a,b)= ↦
=constrain_eq(select(g, a, b), b)=, =assert_bits(w,n)= ↦
=constrain_bits(select(g, w, 0), n)=, =assert_boolean= likewise — with
no ambient guard the path is unchanged (zero movement on every straight-
line circuit; the dump instrument proves it). Add three tests to
v3_guard_scope.rs. Correct VERIFICATION.md:197 either way.

** 3. §4.3 MEDIUM — the other half: =witness_guarded= is still verbatim
=witness_guarded= (v3.rs:859) passes =Some(Arg::Val(guard.val))= straight
through; =public_transcript_input_guarded= (892) now calls =resolve_guard=.
So the =_guarded= family is now inconsistent WITH ITSELF, and
=own_public_key_guarded= (std v3.rs:2197) inherits the verbatim regime.
Inside a =when=, a =_guarded= witness consumes the private transcript
when =inner && !outer=, desynchronising every later witness — the exact
class =da794c5= fixed for the public side, invisible to honest-preimage
differentials. Two callers in std/ledger.
Proposed: one-line fix (=resolve_guard= in =witness_guarded=), a mirror
regression test, dump-gated (expect zero movement — no corpus circuit
runs a =_guarded= witness under a scope, or da794c5's sweep would have
seen it). Also record: =contract_call= (ledger lib.rs:2403) reads its
callee witnesses with ambient-only =c.witness= and emits with the explicit
guard, and no corpus circuit exercises a non-trivial guard on a call —
whether =contract_call(c, g=false, ..)= at top level should consume the
callee's witnesses is unverified against compactc.

** 4. §3.5 + §4.5 — the disclosure manifest is opt-in, and a set

is the CI item and stays out of scope.
