#+title: Contract-API ergonomics (M9): entry points, disclosure declarations, rusty interfaces

Design agreed with dmd 2026-08-14 (session discussion; survey by Plan agent).
This file is the design of record for M9 — phases and decisions below are
settled unless dmd reopens them.

* Survey facts the design rests on
- The differential comparator (assert_call_compatible, e.g.
  erc20_vault_differential.rs:275) compares only the input schema's TYPE
  column (nearly all Scalar<BLS12-381>), the output schema, pi_skips, pis.
  Argument NAMES are cosmetic (ledger-abi.org §6 says so); argument ORDER
  is the real contract (feeds the commitment + preimage layout), and a
  same-typed permutation is caught only by PI equality. Hence phase 0:
  an interface-snapshot instrument, frozen at HEAD, before any port.
- compactc does NOT flatten struct args with underscore paths — it emits
  the repeated base name (%depositRequest.5, %depositRequest.6).
  depositRequest_erc20Address is OUR convention (strictly more
  informative). DECIDED: keep ours.
- v3 has no scalar wrapper types: circuits pass raw Wire3<FieldT,Private>
  and hand-write assert_bits in a block parallel to the c.arg block
  (deposit: 7+7 lines, claim: 13+13, agreeing by eye). Nothing ties
  Compact's Uint<64> to our assert_bits(w, 64) — an under-constrained arg
  is invisible to PI equality on honest preimages. The typed-argument
  layer closes a soundness hole, not just an ergonomics gap.
- Witnesses are NOT entry-point arguments: Compact declares them at
  module level and calls them in the body; common::witness_sk already
  mirrors that. They stay out of the signature (optional #[witness]
  decorator later, low priority).
- Builder3::input asserts all inputs precede instructions — the
  declare-then-constrain two-phase split must live in the API (entry()).
- Prior art: ic-cdk (CandidType: ONE trait yields both schema and
  materialization so they cannot disagree; macro is a shim) and NEAR
  (#[near_bindgen]: per-method struct whose fields are the fn params).

* The design
** Typed v3 leaves (minocrab-std/src/v3.rs)
#+begin_src rust
#[repr(transparent)] pub struct Uint<const BITS: u32, V: Vis3 = Private>(Wire3<FieldT, V>);
#[repr(transparent)] pub struct Bool<V: Vis3 = Private>(Wire3<FieldT, V>);
#[repr(transparent)] pub struct Bytes<const N: usize, V: Vis3 = Private>(Wire3<FieldT, V>); // N ≤ 31
#+end_src
DECIDED (dmd): const-first Uint<64> with V defaulted, accepting the
inconsistency with B32<V>/BytesN<V,N> parameter order — the Compact
side-by-side wins for argument types. .field() unwraps to the raw wire
(zero instructions). B32/BytesN<V,N> stay as they are.
DECIDED (dmd): where possible, methods should also accept native Rust
values (u64 etc.) — via impl Into<Operand> immediates (see literals
phase) and typed const constructors with compile-time range checks.
Native types can't BE argument types (args are wires), but they should
flow into constant/operand positions without ceremony.
DECIDED (dmd): users must be able to derive their own argument types
following the Compact FAB rules — #[derive(CircuitArg)] on their structs
is the mechanism; hand-impls of CircuitArg for custom leaves allowed.

** CircuitArg: one trait = schema + materialization + constraints
const SLOTS; push_atoms (FAB atoms); declare(c, &ArgPath) (ONLY c.arg
calls, names from the path); constrain(&self, c) (exactly compactc's
input constraints, slot order). ArgPath builds depositRequest_erc20Address
style labels (head + _-joined segments; structural suffixes _hi/_lo/_{i}/
_is_some/_is_left come from the leaf impls, stated once).
Leaf table: Uint<BITS>=1 slot/bytes ceil(BITS/8)/assert_bits(BITS);
Bool=1/bytes 1/assert_boolean; Bytes<N≤31>=1/bytes N/8N bits;
B32=2 (path_hi, path_lo); BytesN<N>=bytes_limbs(N) (path_0..); arrays
(path_{i}); Maybe (1+T, path_is_some); Either (1+A+B, path_is_left).
Struct impls: field order IS the wire contract (rule precedented in
signet.rs).

** CircuitArgs + entry()
CircuitArgs: SLOTS / declare / constrain / atoms — the whole argument
list (per-circuit struct, later macro-generated). entry() owns
Circuit3::new → A::declare → debug_assert arg_count == SLOTS →
A::constrain → body → CircuitOut::emit → finish(true).
dmd's original wrap(("names",..), |tuple|..) sketch rejected for: two
hand-parallel lists that desync silently; hand-flattening at call sites;
strings carry no width so no assert_bits; tuple arity at 13+ args.

** Return values / CircuitOut
DECIDED (typed return — dmd's Discloses<D, R> sketch implies it):
circuits return real values mapped through CircuitOut to c.output calls
(matches Compact's `: Bytes<32>`). CircuitOut implemented ONLY for
Public-visibility types ⇒ returning is disclosing, compiler-enforced;
a private value must pass disclose() to be returnable. Output schema is
pinned by the differentials (ours.outputs == theirs.outputs), so
CircuitOut impls carry the output atom order the same way CircuitArg
carries the input order.

** Disclosure declaration (DECIDED: option B, typed labels)
#+begin_src rust
label!(RequestId = "request id");           // zero-sized label type
#[circuit]
fn deposit(c, ...) -> Discloses<(DepositorCommitment, RequestId, RequestRecord), Bool<Public>> {
    ... let key = c.disclose_as::<RequestId>(rid_b32); ... Discloses::of(ok)
}
#+end_src
- Discloses<D, R = ()> is a REAL zero-cost wrapper (PhantomData<D> +
  value: R), constructed with Discloses::of(..) — works in the non-macro
  core; the macro does no signature surgery. (Confirmed by dmd; standing
  principle for all of M9: prefer real types over macro rewriting — the
  more the macros do, the more rust-analyzer/tooling struggle, and real
  types give better type errors. Macros only generate impls/shims that
  could have been written by hand.)
- disclose_as::<L> on multi-wire values (B32 etc.) fans out to the limb
  disclosures under one symbol (the current "request id (hi)/(lo)" pairs
  become one label type). Labels are per logical value, not per limb.
- Enforcement split: rustc checks the SYMBOLS (typo/rename = compile
  error; declaration, call sites, generated test share one type). The
  set-equality of declared vs actual is a macro-GENERATED #[test]
  running the simulator — full static enforcement would need type-state
  threading of a label set through &mut c (rejected as baroque).
- dmd's proviso: acceptable only if the failure is not confusing. So the
  generated test's assertion message is part of the design: it must name
  the circuit and print "declared but never disclosed: [..]" /
  "disclosed but not declared: [..]" with the fix spelled out. It is a
  plain test failure, never a type error.
- Also generated (feature-gated, needs preimage): a valued disclosure
  report golden via minocrab-sim v3 report.
- Prerequisites: v3 Disclosure must carry the Identifier (today index: 0,
  crates/minocrab/src/v3.rs:572) and minocrab-sim needs a v3 report()
  twin (~30 lines).
- Rejected: const-assertion variant (circuits are built at runtime;
  nothing const to assert) — do not re-litigate.

** #[circuit] / #[derive(CircuitArg)] (crates/minocrab-macros)
proc-macro crate, syn 2 + quote; re-exported from minocrab behind a
default-on `macros` feature; depends on nothing of ours (emits paths).
#[circuit] on fn deposit(c: &mut Circuit3, evm_nonce: Uint<64>, ...)
generates: hidden __deposit_Args struct + CircuitArgs impl + pub fn
deposit() -> Compiled3 calling entry(). THINNESS RULE: the expansion
contains NO Circuit3 method call — everything via entry/CircuitArg;
enforced by a cargo-expand/trybuild golden + review grep.
Naming: mechanical snake_case → lowerCamelCase (reproduces 53/53
existing leaf labels); #[arg(name = "...")] escape hatch. Accepted
consequence: hand-abbreviated labels (claim's respond_bigR_x) lengthen —
name-only movement, visible in the interface snapshot.

** Later phases (each separately gated)
- Maps: #[derive(Ledger)] on a struct mirroring the Compact export
  ledger block → declaration-order indices + typed LedgerMap<K,V> with
  Compact's method names (member/lookup/insert/remove/size/is_empty),
  atoms derived via a LedgerRepr trait (kills hand-written value_atoms —
  a real PI-bug hazard — and the hand-maintained index consts).
  REJECTED on the no-hidden-cost rule: Index/map[k] sugar, Deref, entry(),
  iterators. Invariant: no method issues more Impact ops than the one
  Compact operation it names; c + guard stay visible.
- Literals: builder methods accept impl Into<Operand> so native Rust
  values become inline v3 immediates — c.less_than(0u64, amount, 128)
  emits NO instruction (today's c.constant emits a Copy just to name an
  immediate). Typed const constructors Uint::<128>::constant(c, v) with
  compile-time range check. CAUTION: removing Copys is exactly the
  row-snapshot's measured blind spot (Copy = 0 rows, see
  const-generics.org) — gate on differentials + hand-reviewed
  instruction-count delta. REJECTED: std::ops overloading (needs hidden
  builder state; hides cost). Note: Meet already gives mixed-visibility
  ops; sprinkled .private() calls are removable noise.
- Assertion predicates (DECIDED dmd 2026-08-15, no macros): deferred
  descriptor types — less_than(a, b) / eq / etc. return an inert
  #[must_use] value describing the check; c.assert(p) lowers it (the
  comparison instruction + assert, emitted at the assert site). Both
  surfaces: free constructors AND methods on the typed leaves
  (amount.gt(0u64) delegates to the free fn). What it buys is soundness
  wearing ergonomics clothing: the bits argument disappears into the
  operand TYPES (today's hand-typed c.less_than(.., .., 128) width is
  the same genus of bug as the old assert_bits blocks), and the constant
  side becomes a checked immediate (shares the Into<Operand> machinery —
  build together with literals). Descriptors carry an optional message
  (Compact's second assert arg, surfaced in simulator failure reports);
  maybe later a guard (.when(g)) — deferred. Scope hard limit:
  comparisons + not/and/or combinators + eval(c) -> Bool escape hatch
  (for branchy circuits wanting the wire). NO deferred arithmetic /
  expression templates (technically possible via Add-etc. returning
  custom types — rejected: hides emission inside operators, breaks the
  no-hidden-cost rule). Rust fact shaping all this: PartialOrd is
  hardwired to return bool, so operator syntax for comparisons is
  unreachable; named constructors are the ceiling. Safety note: an
  unasserted descriptor emits NOTHING (+ must_use warning) — strictly
  safer than today's unasserted c.less_than, which emits cost and
  constrains nothing with no lint. Port note: lowering moves to the
  assert site; comparisons contribute no PIs and rows are
  position-independent, but keep asserts adjacent to the old let sites
  and lean on the gates. Consequence for port style: predicates want
  typed leaves flowing THROUGH bodies (types carry the widths), so the
  boundary-only .field() unwrap style evolves toward keeping leaves
  typed until raw arithmetic needs wires.
- Showcase twin (DECIDED dmd 2026-08-15): alongside the zero-movement
  direct ports (which remain the differential/benchmark reference), a
  "modern" rewrite of the erc20-vault circuits using every M9 feature to
  fullest effect — typed leaves throughout, predicates, #[circuit],
  Discloses, typed maps, inline immediates. Key insight making this
  honest rather than a demo: the M3/M4 equivalence criterion (same typed
  I/O schema + equal pis/pi_skips on a shared ProofPreimage) leaves the
  instruction stream FREE — so the showcase is corpus-verified against
  compactc's artifacts by the same differential harness, plus property
  tests, and gets its own row/interface snapshot entries (its row counts
  may legitimately differ — e.g. fewer Copys — and are reported, not
  hidden). Lives beside the direct ports (e.g. a showcase module in
  minocrab-contracts); becomes the README's honest source for the
  full-featured snippet. Timing: after phase 7 lands the features it
  exercises (call it phase 8).

* Phasing (M9 bullets mirror this)
0. Interface-snapshot test: ordered (label, type) of ir.inputs +
   ir.outputs + witnesses, all 55 circuits, frozen at HEAD (instrument
   first, like row_snapshot was for const generics).
1. Typed leaves Uint/Bool/Bytes<N≤31> (v3).
2. CircuitArg/ArgPath/CircuitArgs/entry/CircuitOut core, hand impls;
   port signet_contract::sign_bidirectional + erc20_vault::deposit.
3. minocrab-macros + #[derive(CircuitArg)]; port withdraw + claim
   (Maybe<Either<..>> = hardest flattening).
4. #[circuit] attribute; re-port the same four (diff = struct→attribute).
5. Mechanical port of the remaining circuits (interface snapshot: name
   column may move where mechanical naming lengthens labels; order/types
   NEVER).
6. Disclosure: Identifier fix + v3 report + label!/disclose_as/
   Discloses + generated tests.
7. Maps + literals + assertion predicates (separate commits, separate
   gates as above; predicates and literals share the Into<Operand>
   machinery).
8. Showcase twin: the modern erc20-vault rewrite, differential- and
   property-tested, own snapshot entries; README snippet then points at
   real code.
Gates for every phase: interface snapshot + row_snapshot + all 13
differential suites; ports must be zero-movement (except documented
name-column changes in 5 and the showcase twin in 8, whose deltas are
reported).
dmd 2026-08-14: if any phase moves measured performance significantly
(realistically only phase 7's Copy-removal; anything else should be
zero-movement), refresh the benchmark — re-run the M6 harness
(nix run .#bench) and update BENCHMARK.md the way the M7 passes did.

* Risks
- Order drift in derived structs = silent preimage change; backstops:
  interface snapshot (slot granularity) + PI equality + the written
  field-order rule.
- declare() emitting an instruction: trips Builder3::input's assert;
  entry() also asserts arg_count == SLOTS.
- Macro-hidden work: thinness rule + expand golden.
- rustc 1.97 stable only — nothing here needs generic_const_exprs
  (SLOTS sums are associated consts, not array lengths).

* As built
** Phase 0 — interface snapshot (crates/minocrab-contracts/tests/interface_snapshot.rs)
Frozen table: one multi-line block per circuit, 55 circuits, in the same
order as row_snapshot; the circuit enumeration both guards share now
lives in tests/support/mod.rs (the frozen tables stay independent).
Regenerator: `--ignored --nocapture print_interface_snapshot`.
What the three sections actually come from (the IR is less forthcoming
than the phasing bullet assumed):
- inputs: IrSource::inputs, read through serde (TypedIdentifier's fields
  are pub(crate) upstream — the same route assert_call_compatible takes).
  The label is Builder3's `%name.index` with the `%` and the `.index`
  uniquifier stripped; index == slot for arguments, so dropping it makes
  an insertion show up as one added line instead of renumbering every
  line after it. Anything not of that exact shape is kept verbatim.
- outputs: the IR's output signature is TYPES ONLY — there are no output
  labels in ZKIR. Recovered by zipping ir.outputs with the
  DisclosureKind::Output records, which Circuit3::output pushes 1:1 with
  the queued outputs; the test asserts the two agree in length.
- witnesses: Compiled3::witnesses is a COUNT, not a list. The ordered
  list is recovered from the instruction stream (Instruction::PrivateInput,
  type + whether the read is guarded), and the count is cross-checked
  against Compiled3::witnesses. Guarded reads are marked, since a guard
  changes whether the transcript is consumed.
Failure output: a line-level LCS diff per changed circuit (`-` frozen,
`+` built), so a reorder reads as one moved line and a rename as one
-/+ pair. The diff renderer has its own unit test.
** Phase 1 — typed v3 leaves (crates/minocrab-std/src/v3.rs)
Uint<BITS, V = Private> / Bool<V = Private> / Bytes<N ≤ 31, V = Private>:
#[repr(transparent)] newtypes over one Wire3<FieldT, V>, with
.field() / from_field() (no instructions) and, mirroring types.rs's v2
leaves, constrain_input() — assert_bits(BITS) / assert_boolean /
assert_bits(8N). That method is the point of the layer: the constraint
now comes from the argument's type instead of a hand-written parallel
block, so phase 2's CircuitArg::constrain just calls it.
- Bounds are inline-const asserts in from_field (BytesN's idiom, so
  every constructor inherits them): 0 < BITS < 255 and 0 < N <= 31.
  The upper Uint bound is not decoration — upstream's ConstrainBits
  passes `bits >= FR_BITS` (255) straight through to
  assigned_to_le_bits' overflow flag, i.e. a Uint<255> would be range-
  constrained to nothing. Both fire as E0080 at compile time (checked).
- Constant constructors take native Rust values today (u64 / bool /
  &[u8; N], the array form so the length is checked by the type) and
  return the Public visibility; the Uint one asserts the value fits
  BITS at circuit-build time, short-circuiting the shift for BITS >= 64
  so it cannot overflow. These still emit c.constant's naming Copy —
  turning them into inline immediates is phase 7, deliberately not now.
- No naming collision with the v2 types.rs Bool/UintN/BytesN: the new
  leaves are reachable only as minocrab_std::v3::{Uint, Bool, Bytes}
  and are NOT added to the crate-root re-export list (which still
  exports the v2 Bool/BytesN).
Tests (crates/minocrab-std/tests/v3_leaves.rs): each leaf's circuit is
compared as serialized ZKIR against the same circuit hand-written over
raw wires — equality is the zero-cost claim, stronger than an
instruction count — plus a 0-instruction check for .field(), the
range-check panic, and the BITS >= 64 no-overflow path. No circuit was
converted (phase 2), and both snapshots stayed bit-identical.
** Phase 2 — the entry-point core (crates/minocrab-std/src/v3/entry.rs)
Placement: minocrab-std, next to the leaves — the core needs both the
leaves and Circuit3/Compiled3, and minocrab-std is the only crate that
already has both (minocrab has no leaves; minocrab-contracts is the
consumer). Reachable as minocrab_std::v3::{...}, re-exported from v3.rs.
Real signatures:
#+begin_src rust
pub struct ArgPath(String);          // root / field / index / suffix / as_str
pub trait CircuitArg: Sized {
    const SLOTS: usize;
    fn push_atoms(atoms: &mut Vec<AlignmentAtom>);
    fn declare(c: &mut Circuit3, path: &ArgPath) -> Self;
    fn constrain(&self, c: &mut Circuit3);
    fn atoms() -> Vec<AlignmentAtom> { .. }   // provided, from push_atoms
}
pub trait CircuitArgs: Sized {
    const SLOTS: usize;
    fn declare(c: &mut Circuit3) -> Self;
    fn constrain(&self, c: &mut Circuit3);
    fn atoms() -> Vec<AlignmentAtom>;
}
pub trait CircuitOut { const SLOTS: usize; fn emit(self, c: &mut Circuit3, label: &str); }
pub fn entry<A: CircuitArgs>(body: impl FnOnce(&mut Circuit3, A)) -> Compiled3;
pub fn entry_out<A: CircuitArgs, O: CircuitOut>(
    label: &str, body: impl FnOnce(&mut Circuit3, A) -> O) -> Compiled3;
#+end_src
The three laws are in the module docs; entry() checks the two checkable
halves of law 1 with plain asserts (NOT debug_assert as the design text
said — the suites run --release, where a debug_assert is compiled out,
and circuit build happens once so the cost is nil): arg_count == SLOTS,
and instruction_count == 0 after declare, so a declare() that computes is
caught even when it is the last one declared. Both counts come from two
new non-circuit-affecting accessors, Circuit3::arg_count /
instruction_count over Builder3::input_count / len.
Leaf impls, Private only (c.arg cannot hand back a public wire, so
"argument ⇒ private" is enforced by the impl set): Uint<BITS> (1 slot,
atom bytes ceil(BITS/8)), Bool, Bytes<N ≤ 31>, B32 (2 slots, _hi/_lo,
8/248 bits, one bytes-32 atom), BytesN<N> (LIMBS slots, _0.., per-limb
widths). CircuitArgs is also implemented for () (the empty argument list,
used by the output test). Arrays/Maybe/Either are NOT here: neither port
needs them and phase 3 ports the circuits (withdraw/claim) that do —
deferred deliberately, with the flattening decided there.
Deviations from the phasing bullet, all deliberate:
- entry() is TWO functions. A circuit that returns nothing has no label
  to give its output, and a returning circuit's label cannot come from
  the argument list; rather than thread an unused "" through every
  call site, entry(body) is the []-returning form and entry_out(label,
  body) the general one (entry delegates to it with O = ()).
- CircuitOut::emit takes the label as a &str parameter. The impls own
  the multi-slot suffixes (B32 emits "{label} (hi)"/"(lo)", matching
  xcontract_events' hand-written labels) but not the base name. Phase 6
  replaces the string with the declared label type; until then this is
  the only honest place for it.
- Discloses<D, R> is NOT built. Without label!/disclose_as there are no
  label types to put in D, so Discloses::of would be a wrapper around
  nothing that phase 6 would immediately rewrite. Deferred to phase 6
  whole, as its design section describes.
- entry() hard-codes finish(true). All 32 finish() calls in
  minocrab-contracts pass true; when a circuit needs false, that becomes
  a parameter (and the differential that needs it will say so).
Tests (crates/minocrab-std/tests/v3_entry.rs): a five-argument list
(Uint<64>, Bool, a nested struct of Bytes<20>+Uint<128>, B32,
BytesN<128> = 11 slots) built through entry() is compared as serialized
ZKIR against the same circuit hand-written over raw wires — byte equality
pins the LABELS too, since Builder3 names every value %label.index — plus
the atom table, the ArgPath rule, and both law violations reaching their
asserts (a lying SLOTS, a declare() that emits an instruction).
** Phase 2 — the two ports
signet_contract::sign_bidirectional: SignBidirectionalArgs { request_id:
B32, notification: Notification { version: Uint<8>, payload:
BytesN<128> } } — one nested struct, so the port exercises the same
path-joining the derive will. erc20_vault::deposit: DepositArgs with the
five scalars + DepositRequest { erc20_address: Bytes<20>, amount:
Uint<128> } (Compact's own field order and names).
Every label the mechanical rule produces equals the hand-written one, at
both circuits, with no escape hatch needed: requestId_hi/_lo,
notification_version, notification_payload_0..4, evmNonce .. keyVersion,
depositRequest_erc20Address, depositRequest_amount. So the interface
snapshot's name column did not move either.
The bodies are unchanged except that `&mut c` becomes `c` (inside the
entry closure `c` is already `&mut Circuit3`) — verified by a
whitespace-and-reborrow-normalized diff of deposit's body: the only other
hunks are the argument block itself and `c.finish(true)` → the closing
`})`. Zero movement everywhere: interface_snapshot, row_snapshot and all
13 differential suites bit-identical/green.
** Phase 3 — #[derive(CircuitArg)] (crates/minocrab-macros)
A proc-macro crate depending on nothing of ours (syn 2 + quote +
proc-macro2, all three already in Cargo.lock transitively, so the lock
gained no new package but minocrab-macros itself). One derive on a
named-field struct emits BOTH impls:
- CircuitArg — SLOTS as `0usize + <FieldTy>::SLOTS + ..`, push_atoms /
  constrain in field order, declare with
  `ArgPath::field(path, "<camelCase>")` per field;
- CircuitArgs — the same fields at the root (`ArgPath::root`), with
  constrain and atoms DELEGATED to the CircuitArg impl so the two cannot
  drift. Consequence (deliberate): a derived struct is usable both as a
  circuit's whole parameter list and as one nested argument; the phase-2
  ports' two struct kinds now need only one derive.
Naming: mechanical snake_case -> lowerCamelCase (`split('_')`, first
segment verbatim, later segments capitalised — `max_fee_per_gas` ->
`maxFeePerGas`, `big_r` -> `bigR`, `erc20_address` -> `erc20Address`;
raw identifiers lose their `r#`). `#[arg(name = "…")]` overrides one
field's segment; anything else inside `#[arg(..)]`, an `#[arg]` on the
struct itself, a tuple struct, or an enum is a compile error.
Where the re-export landed (the design said "re-exported from minocrab
behind a default-on macros feature"): the core lives in minocrab-std, so
the derive is re-exported as `minocrab_std::v3::CircuitArg` — the SAME
name as the trait it implements (trait in the type namespace, derive in
the macro namespace, as `serde::Serialize` does), so the `use` the ported
files already had brings both. Feature: minocrab-std's default-on
`macros` (`dep:minocrab-macros`, optional). The expansion names exactly
two upstream types (Circuit3, AlignmentAtom); they come from a
`#[doc(hidden)] pub mod minocrab_std::v3::__private`, so generated code
needs only `minocrab_std` in scope and the macro crate stays a leaf.
THINNESS RULE, enforced two ways: a unit test in the macro crate asserts
the expansion's token string contains no method call on the circuit
(`"c ."`) and no `Circuit3 ::` associated call; and the real gate,
crates/minocrab-std/tests/v3_derive.rs, builds a derived argument list
through entry() and compares serialized ZKIR byte-for-byte against (a) the
hand-written impl and (b) a raw `c.arg` block spelling every label out —
which pins the camelCase rule and the `#[arg(name)]` override, since
Builder3 names every value `%label.index`. No trybuild/macrotest golden:
neither is in the lock file and neither is worth a new dev-dependency
when byte-identical ZKIR is the stronger statement.
** Phase 3 — arrays / Maybe / Either
v3 had NO Maybe/Either at all: data.rs's are v2 (Bundle<V>-based, over
`Circuit`), and the v3 circuits hand-flattened the shapes into raw wires
(claim's five recipient slots; CoinRecipient is the hand-rolled Either).
So the phase added the two argument-side types to v3.rs next to
CoinRecipient — `Maybe<T, V: Vis3 = Private> { is_some: Bool<V>, value: T }`
and `Either<A, B, V: Vis3 = Private> { is_left: Bool<V>, left: A,
right: B }` — payload-first with the visibility defaulted, the parameter
order the design chose for argument types (Uint<BITS, V = Private>).
They are NOT in the crate-root re-export list, which still exports v2's
data::{Maybe, Either}.
Slot layouts (entry.rs), all confirmed against claim's frozen labels:
- `[T; N]`: N * T::SLOTS, element i under `path.index(i)`. declare()
  builds through a Vec rather than `array::from_fn`, whose call order is
  not part of its contract — here the order IS the wire layout.
- `Maybe<T>`: 1 + T::SLOTS. The tag takes `_is_some` and the value keeps
  the PARENT's path: a Maybe adds a slot, not a level
  (`recipient_is_some`, then straight to `recipient_is_left`). That is
  what the hand-written claim does, and Compact's `value` field name
  never appeared in a label.

** Phase 4 — #[circuit] (crates/minocrab-macros/src/circuit.rs)
Expansion shape, for `#[circuit] pub fn deposit(c: &mut Circuit3, evm_nonce:
Uint<64>, …, deposit_request: DepositRequest)`:
#+begin_src rust
pub fn deposit() -> ::minocrab_std::v3::__private::Compiled3 {
    struct __deposit_Args { evm_nonce: Uint<64>, .., deposit_request: DepositRequest }
    impl CircuitArg for __deposit_Args { .. }   // the derive's own codegen
    impl CircuitArgs for __deposit_Args { .. }
    fn __deposit_body(c: &mut Circuit3, evm_nonce: Uint<64>, ..) { <body, verbatim> }
    ::minocrab_std::v3::entry(|__c, __args: __deposit_Args| {
        __deposit_body(__c, __args.evm_nonce, .., __args.deposit_request)
    })

#+end_src
Two decisions worth writing down:
- Everything but the public fn is scoped INSIDE its body. Two circuits in
  one module then cannot collide (erc20_vault has nine) and nothing hidden
  reaches the module namespace; items in a fn body still resolve the
  module's `use`s, so the generated impls need no imports of their own.
- The body is MOVED, not rewritten: a real fn with the parameters as
  written, called from the closure. Spans, type errors, `return` and
  rust-analyzer behave as if the attribute were absent — the standing
  "real types over macro rewriting" principle applied to the body itself.
  An unused argument is legitimate (a slot can exist only for the wire
  shape) and warns like any unused parameter; the fix is Rust's own
  leading underscore, which does not move the label (`_recovery_id` and
  `recovery_id` both camel-case to `recoveryId`).
Shared codegen, not a second copy: circuit_arg.rs exposes
`impl_arg_traits(name, generics, &[ArgField])` and `arg_label(ident, attrs)`;
the derive and the attribute differ only in where the ArgField list is
collected (struct fields vs parameters after `c`). So the camelCase rule and
`#[arg(name = "…")]` — written on the PARAMETER for the attribute — are one
code path. The hidden struct gets BOTH impls, since the derive's CircuitArgs
delegates constrain/atoms to its CircuitArg.
Return types, as phase 2 actually built them: `()` (however spelled) maps to
`entry`, anything else to `entry_out(label, ..)` with the label from
`#[circuit(output = "…")]`. The label is required there and rejected on a
returnless circuit — entry_out's label is still a string, so there is
nowhere else for it to come from until phase 6 makes it a declared label
type. Discloses<D, R> was not touched. None of the four ported circuits
returns anything (all are Compact `: []`), so entry_out has only the tests
as a user for now.
Error inventory (each with its own span, unit-tested against expand()'s
Result — still no trybuild): missing first parameter / first parameter not
`&mut Circuit3` / `self`; generic parameters; where-clause; async; unsafe;
const; extern ABI; variadic; a parameter that is not a plain `name: Type`
(`_`, tuple pattern, `ref`, sub-pattern); an unknown attribute on a
parameter; `#[arg]` on the circuit parameter itself; an unknown `#[circuit]`
argument or a repeated `output`; and both halves of the output-label rule.
The first-parameter check is by NAME (a path ending in `Circuit3`), which
rejects an aliased spelling — deliberate: the message is worth more than the
alias.
Gates: the thinness unit test now covers the attribute (the scaffolding
contains no `c .` and no `Circuit3 ::`; the fixture body is empty, since the
author's body is copied verbatim and is naturally full of circuit calls),
and the real one is crates/minocrab-std/tests/v3_circuit.rs — the same

*** New in the core: minocrab_std::v3::Secp256k1Point
The corpus's only curve-point argument (initialize ×3, attest's
verifyOnly/shaVerify/keccakVerify, test_caller's initialise — 7 circuits),
and the first argument leaf whose slot is NOT a `Wire3<FieldT, _>`. That is
the whole difficulty: `CircuitArg::push_slots` hands back native field
wires, and a `Point<Secp256k1>` slot has none to hand back.
- The leaf (v3.rs, beside the ECDSA gadgets): a `#[repr(transparent)]`
  newtype over `Wire3<Secp256k1PointT, V>` with `from_point`/`point`.
- `CircuitAbi`: SLOTS = 1, prims = `[Prim::Point]`, atoms = `encode()`'s
  five limbs (x 24+8, y 24+8, the infinity field, notes/ledger-abi.org §3).
  One slot, five atoms — the same slots-vs-atoms split a `Bytes<32>` has in
  the other direction.
- `CircuitArg::push_slots` pushes NOTHING, and the provided `constrain`
  filters `Prim::Point` out of the prims before zipping. The filter is the
  statement of law 3, not an exception to it: compactc's own table is
  `[(tpoint ,ctype) instr*]` — no constraint — so a point slot has nothing
  to be zipped against, and everything a slot list is used for (constraints,
  FAB hashing) is native-field work. It lives in the ONE provided
  `constrain`, so no impl gets an opinion about it.
- Gate: `crates/minocrab-std/tests/v3_entry.rs`, a three-argument list with
  the point in the MIDDLE, compared as serialized ZKIR against the
  hand-written `c.arg::<Secp256k1PointT>` circuit (so the slot's POSITION is
  pinned, not just its absence of constraint), plus the atom table.
Rejected: widening `push_slots` to an enum or `Option` slot. It would have
touched every impl and both hash flavors' call sites to describe one
argument type that carries no constraint anyway.

*** Left unported, and why: hashing's Bytes<len> family (16 rows)
`control`/`persistent`/`keccak`/`transient` take their input WIDTH as a Rust
parameter — the experiment SWEEPS 32/64/128/256/1024 in a loop
(`tests/hashing_differential.rs`) — while a `CircuitArg` is a type and
`CircuitArgs::SLOTS` is a `const`. The two ways out are both worse than the
status quo: const-generic entry points (`control::<32>()`) that the sweeping
loops cannot call, or a `match` over the sizes swept today, which turns a
general experiment into a closed enumeration that panics on the next size
someone measures. And the port would buy nothing HERE: the soundness the
typed layer exists for is already present, because `BytesNDyn::
constrain_input` derives the per-limb widths from the same `len` that
declared the limbs — there is no hand-written parallel block to drift.

whose shape is fixed, IS ported — so the file shows both.)

*** Gotchas for the next port
- `#[circuit]` generates `pub fn name() -> Compiled3`, taking NOTHING. A
  circuit family parameterized by a Rust value (events' `emits`, xcall's
  `n`) therefore uses `entry(|c, args: SomeArgs|)` with a derived struct;
  the typed-argument guarantee is identical, only the entry point's spelling
  differs. Same for a body shared by two entry points (attest's hashes).
- Renaming a PARAMETER renames its slots. The borsh fork's settle circuits
  briefly became `output: VaultResponse` and moved four interface lines to
  `output_kind`/`output_success`; the parameter is `serialized_output`, with
  a `let output = serialized_output;` for the body. An unused parameter's
  leading underscore does NOT move a label (`_recipient` → `recipient`),
  which is what mint_tokens' declared-but-unused recipient and xcall's
  `_data` rely on.
- Unused STRUCT FIELDS do not warn, which is how the settle circuits keep
  `respond.bigR.y` and `respond.recoveryId` (wire shape, read by nothing)
  without ceremony.

*** The record: v3 Disclosure carries the Identifier
`minocrab::v3::Disclosure3 { label: String, kind: DisclosureKind, values:
Vec<Identifier> }` — v3's own record, replacing the shared v2 `Disclosure` in
`Circuit3`/`Compiled3`. Two changes in one:
- the Identifier fix the design named: v2 points at a ZKIR memory INDEX,
  which v3 does not have, so the v3 record used to store `index: 0` and every
  value in a v3 report would have read `<not computed>`. It now carries the
  `%label.N` identifiers — what the instruction stream refers to and what the
  simulator keys its memory by. New non-circuit-affecting accessor
  `Builder3::identifier(Val) -> Identifier` (`name` was private).
- `values` is a LIST, because one record is one LOGICAL value: a `Bytes<32>`
  disclosed under one label contributes both limbs to one record instead of
  two records called `"… (hi)"` / `"… (lo)"`. That is what makes a declared
  set comparable to a disclosed one — labels are per value, not per wire.
Rejected: an `Option<Identifier>` bolted onto the v2 `Disclosure` (always
`None` on the v2 side, and v2's `index` would have to become an enum), and a
generic `Disclosure<R>`. A v3-only twin beside the v2 one says the true
thing: the two frontends name values differently.
Primitives on Circuit3 (the only places a `Disclosed` record is made):
#+begin_src rust
pub fn disclose<T: IrTy>(&mut self, w: Wire3<T, Private>, label: &str) -> Wire3<T, Public>;
pub fn disclose_all<T: IrTy, const N: usize>(
    &mut self, label: &str, wires: [Wire3<T, Private>; N]) -> [Wire3<T, Public>; N];
pub fn disclose_slice<T: IrTy>(
    &mut self, label: &str, wires: &[Wire3<T, Private>]) -> Vec<Wire3<T, Public>>;
#+end_src
`disclose` is `disclose_all` at N = 1, so the free-string form still works and
still records one wire. A disclosure of ZERO wires records NOTHING (see the
gotchas).

*** The vocabulary (crates/minocrab/src/v3/disclose.rs)
#+begin_src rust
pub trait DisclosureLabel: 'static { const LABEL: &'static str; }
label!(RequestId = "request id");            // macro_rules!, #[macro_export]
label! { /// docs and a visibility are accepted
         pub RequestRecord = "request record"; pub Caip2Id = "the CAIP-2 chain id"; }
pub trait LabelSet { fn push_labels(labels: &mut Vec<&'static str>);
                     fn labels() -> BTreeSet<&'static str> { .. } }
pub trait Disclose: Sized {
    type Public;
    fn disclose_as<L: DisclosureLabel>(self, c: &mut Circuit3) -> Self::Public;
}
pub struct Discloses<D, R = ()> { value: R, _labels: PhantomData<fn() -> D> }
impl<D, R> Discloses<D, R> { pub fn of(value: R) -> Self; pub fn into_inner(self) -> R }
pub trait Declared { fn declared() -> BTreeSet<&'static str>; }
impl<D: LabelSet, R> Declared for Discloses<D, R> { .. }

pub fn assert_declared_disclosures<T: Declared>(circuit: &str, compiled: &Compiled3);
#+end_src
PLACEMENT deviates from the design's "minocrab-std": the vocabulary is in
minocrab (the frontend), because `minocrab_ledger::contract_call` DISCLOSES —
a cross-contract call publishes the callee's entry-point hash, the
communications commitment and the result limbs — and minocrab-ledger does not
depend on minocrab-std. Those labels have to be nameable in the CALLER's
declaration, so they are now `minocrab_ledger::{XcallEntryPointHash,
XcallCommitment, XcallResult}`, written with the same `label!`.
minocrab-std keeps the half that needs its types
(crates/minocrab-std/src/v3/disclose.rs): `Disclose` impls for `Uint<BITS>`,
`Bool`, `Bytes<N>`, `B32`, `ContractAddress`, `Secp256k1Point`, `BytesN<N>`
and `ShieldedCoinInfo3` (the whole coin under one label), plus
`impl<D, R: CircuitOut> CircuitOut for Discloses<D, R>` — `CircuitOut` is
minocrab-std's trait, so the impl must live there. Everything is re-exported
from `minocrab_std::v3`, so contracts still write one `use`.
No blanket `impl<L: DisclosureLabel> LabelSet for L`: it would overlap the
tuple impls (a downstream crate may implement `DisclosureLabel` for a tuple of
its own types), so `label!` emits the `LabelSet` impl per label and the
tuples are written out to arity 16.

*** disclose_as is a method on the VALUE, not on the circuit
The design sketched `c.disclose_as::<RequestId>(rid_b32)`. That spelling is
unreachable: such a method needs TWO type parameters (the label and the
value), and a turbofish must supply all of a function's type arguments or
none — `error[E0107]: method takes 2 generic arguments but 1 generic argument
was supplied`, checked. The options were `c.disclose_as::<RequestId, _>(v)`
and `v.disclose_as::<RequestId>(c)`; the second keeps the design's
`disclose_as::<L>` spelling exactly and reads well next to the Compact source
(`const requestId = disclose(calculateRequestId(request))` becomes
`let request_id = request_id.disclose_as::<RequestId>(c);`). The trait is
`Disclose`, so `.disclose_as` needs it in scope (it is in the crate's usual
`use minocrab_std::v3::{..}` line).

*** The declaration must not move the interface
`Discloses<D, R = ()>` is a real zero-sized wrapper; its `CircuitOut` impl is
`R`'s, so `Discloses<D, ()>` occupies NO output slot. `#[circuit]` routes it
to `entry` (the label-less form) exactly as a `-> ()` circuit, and only
`Discloses<D, R>` with a non-unit `R` demands `#[circuit(output = "…")]`.
That is the answer to "a declaration is not a return value": the vault's nine
`[]` circuits gained a return TYPE and no output. `entry` was widened from
`impl FnOnce(&mut Circuit3, A)` to `impl FnOnce(&mut Circuit3, A) -> O` with
`O: CircuitOut` and a plain `assert_eq!(O::SLOTS, 0)`, which is also what
lets a hand-written `entry(|c, args| { ..; Discloses::of(()) })` declare.
The macro reads the return type SYNTACTICALLY (last path segment is
`Discloses`; whether a second, non-`()` type argument is present) — the same
shallow reading `is_circuit_ref` already does on the first parameter. An
aliased spelling is not recognised, deliberately: the declaration is meant to
be legible in the signature.

*** Piece 2 — inline-immediate literals, and the delta review
`Operand<T, V>` (crates/minocrab/src/v3.rs) is what every operand position
now takes: `add`, `mul`, `neg`, `inv`, `not`, `test_eq`, `less_than`,
`cond_select`, `assert_eq` are all `impl Into<Operand<T, V>>`. A wire
converts; so do `u64` / `u32` / `u8` / `bool` / `Fr`, at `FieldT` and

A predicate emits NOTHING until `c.assert(p)` or `p.eval(c)`; unasserted it
costs nothing and warns, which is strictly safer than today's unasserted
`c.less_than(..)` — that one emits cost, constrains nothing, and no lint
says so.
What it buys, both halves soundness:
- the WIDTH comes from the operand types. Two typed operands must agree
  ("comparing a 128-bit value with a 64-bit one…"), one typed operand
  supplies it, and an ORDERING of two raw wires is a build-time panic naming
  the fix (equality needs no width, so raw wires are fine there);
- the constant side is a CHECKED immediate: a literal is range-checked
  against the width the comparison runs at, so `less_than(byte, 300u64)` on
  a `Bytes<1>` panics instead of comparing against an unrepresentable value.
Lowering, stated once and tested byte-for-byte: `less_than` → `less_than a b
bits`; `greater_than` → the same instruction with the operands swapped; `le`
/ `ge` → that plus a `not`; `eq` → `test_eq`; `ne` → `test_eq` + `not`;
`and` → `mul`; `or` → `!(!x && !y)`, written out rather than folded, because
a combinator that quietly simplified would be hiding cost.
MESSAGES are metadata, exactly like disclosure records: no instruction, no
slot, no row. `Circuit3::assert_with` records `(instruction index, message)`
on the circuit, `Compiled3::assert_messages` carries the list, and
minocrab-sim spends it — a failed run says `instruction 41 (assert): failed
assertion: Chain ID must be positive` instead of `failed direct assertion`.
ZKIR has nowhere to put Compact's second `assert` argument, which is why it
lives beside the stream.

*** Overhead-for-ergonomics candidates for dmd (phase 7)
dmd 2026-08-15 loosened the "zero circuit overhead throughout" principle:
where a small overhead would buy a clear ergonomic win, he wants to be ASKED
with numbers rather than have the option auto-rejected. Phase 7 took NO
overhead — every piece is byte-identical or a reviewed Copy removal — so
what follows is the list of places where the zero-overhead (or
zero-movement) rule shaped the API, each with what it would cost. Rows are
Midnight's own cost model, measured on single-instruction circuits.
Reference numbers: `less_than` costs 8 rows at ≤32 bits, 11 at 64, 17 at
128, 23 at 192; `constrain_bits` costs ~bits/4 rows (2 at 8, 16 at 64, 32 at
128); a `copy` of an immediate costs 0.

1. MAPS — straight-line methods with the guard as an inline immediate.
   Today every method takes the guard, and a straight-line circuit threads a
   `one` wire through ~100 call sites and every helper signature
   (`map.member(c, one, &key)`). The guard operand could be the immediate
   `1` (v3 guards are operands), giving `map.member(c, &key)`.
   COST: zero rows — it REMOVES a `Copy`. What it costs is MOVEMENT: the
   impact instruction's guard reads `0x01` instead of `%imm.N`, so the
   artifact is no longer byte-identical to compactc's stream. It is the
   byte-identity gate that blocks this, not overhead; the showcase twin
   (phase 8) is where it would be free to land.
2. MAPS — typed cells for values whose limbs are COMPUTED. `mpcResponseKey`
   (a curve point, limbs from an `encode` instruction) and coin cells are
   `LedgerField`s with explicit ops, because `LedgerRepr::push_limbs` cannot
   emit. Giving it `&mut Circuit3` would make them ordinary
   `LedgerCell<T>`s.
   COST: zero instructions — the `encode` is emitted at the call site today
   anyway. The price is the invariant that a repr never emits, which is what
   currently makes "building a LedgerValue is free" obvious by construction.
3. PREDICATES — mixed-width comparisons instead of a build-time panic.
   `less_than(u64_value, u128_limit)` panics today ("comparing a 64-bit
   value with a 128-bit one"); it could compare at the wider width, which is
   sound because each operand fits its own type.
   COST: +6 rows for a 64→128 widening (11 → 17), +9 for the widest
   realistic case (8→128). Buys: no manual widening, no panic to work
   around.
4. PREDICATES — orderings on RAW WIRES, made sound rather than rejected.
   `less_than` is UB if an operand exceeds the width, so a wire with no type
   is refused. The predicate could EMIT the range constraint the comparison
   assumes.
   COST: ~bits/4 rows per unconstrained operand — 16 rows at 64 bits, 32 at
   128. Buys: predicates work on values already unwrapped to wires (swap's
   tokenIn/tokenOut, the settle circuits' output limbs) instead of pushing
   the author back to `c.less_than(.., bits)`, where the width is hand-typed
   and unchecked again — which is the very bug this piece exists to remove.
5. PREDICATES — a boolean LEAF (`is_true(bool_wire)`), so the combinators
   and `.message(..)` work with a computed boolean (a map `member` result,
   an in-branch guard).
   COST: ZERO rows and zero instructions (it lowers to the wire itself).
   Blocked by the design's hard scope, not by overhead; recorded because the
   gap is real — those sites use `c.assert_with(cond, Some(msg))` and
   `common::assert_if_with` instead of reading like the rest.
6. PREDICATES — `.when(guard)`, the deferred in-branch form.
   COST: ZERO — the lowering is `assert(select(guard, cond, 1))`, exactly
   what `common::assert_if` emits today. It would fold the in-branch assert
   idiom into the predicate surface rather than keeping a second spelling.
Still rejected on their merits, no numbers needed: `map[k]` (an `Index` impl
cannot take `c`), iterators over a ledger map (no in-circuit meaning), and
deferred ARITHMETIC (`a + b` returning a descriptor hides emission inside an
operator).

**** C1 — the guard-free methods, and why the plain name is theirs
Compact writes `map.member(key)`: it has no guard argument at all, and ours
exists only because an Impact instruction carries one. So the plain name is
the straight-line form, `_under` takes a wire (an effect inside a branch), and
`_guarded` is unchanged (a READ inside a branch, guard on the transcript gates
too). The guard being an operand is what makes the straight-line form
possible: it inlines the immediate `1` instead of naming a `Copy`.
COST: zero rows, MINUS one instruction per circuit that no longer needs to
name a `1`. What it costs is byte-identity with compactc, whose guard operand
IS that named wire — so the three direct ports were mechanically moved to
`_under` (66 call sites, one script, three files) and keep their streams, and
only the twin uses the plain names. That mechanical move is itself gated: all
78 circuits' serialized ZKIR dumped before and after, 78 of 78 byte-identical.

**** C2 — a repr may emit, and what that costs
`push_limbs` taking `c` is the smaller half. The bigger half is
`witness_read`, the READ side: a `Secp256k1Point` cell mints ONE TYPED gate
and derives its five FAB limbs with an `encode` instruction, which no
limb-by-limb read can express. With both halves the point cell is an ordinary
`LedgerCell<Secp256k1Point<Public>>` and `common::cell_read_point` is only the
ports' spelling; `deployer` became a `LedgerCell<B32<Public>>` at the same
time. `signetSigner` stays a `LedgerField` — it is a sealed HANDLE read
through the interface crate, not a value.
THE PRICE, recorded because phase 7 named it: "building a `LedgerValue` is
free" is no longer true by construction. What replaces it is narrower and
still checkable — a repr emits exactly the instructions the call site would
have emitted itself, immediately before the op — and it is what
`tests/v3_ledger.rs`'s byte-equality against the explicit form asserts.
One honest wart: `Secp256k1Point::from_limbs` is `unreachable!`, because ZKIR
has `encode` and no inverse. It is unreachable through `LedgerCell` (which
goes through `witness_read`), and reachable only by declaring a
`LedgerMap<_, Secp256k1Point>`, which Compact cannot declare either; the panic
message says so and names the two supported shapes.

**** A/B expressed as COMPILE errors (the standing principle applied)
Both rejections the phase-7 module documented as build-time panics are now
`error[E0080]` at the call site, from inline `const` asserts in the comparison
constructors — checked by compiling both spellings:
#+begin_example
error[E0080]: evaluation panicked: the two operands of a comparison have different
widths … or widen the narrow one explicitly with `.widen::<BITS>()`
  … evaluation of `less_than::<Uint<128>, Uint<64>>::{constant#0}` failed here

error[E0080]: evaluation panicked: an ordering comparison needs a width and neither
operand's type carries one: compare TYPED values (a `Uint<BITS>`, a `Bytes<N>`)
  … evaluation of `less_than::<Wire3<FieldT, Private>, Wire3<FieldT, Private>>::{constant#1}`
#+end_example
NOT as a missing `CheckOperand` impl for `Wire3`, which was the requested
shape and is the nicer error, for one reason that covers both halves: the
condition is a property of the PAIR. A raw wire on ONE side of a typed
comparison is sound (the type supplies the width) and is what the frozen ports
use — `amount.gt(zero.private())`, where the `zero` is also needed as a wire
elsewhere so it stays named — and "at least one of A, B carries a width" is
not sayable in a trait bound without overlapping impls. Dropping the impl
would have rejected ten sound call sites in the ports and forced call-site
changes that MOVE their streams.

**** Panics that could NOT become compile errors, and why
1. `predicate::check_literal_fits` — "the literal 300 does not fit the 8 bits
   the comparison runs at". The magnitude of a runtime integer is not in the
   type system: `300u64` is a value, not a type. A stricter form would need
   the literal as a const generic (`lit::<300>()`), which is a different API
   and dmd's call, not this phase's.
2. `Uint::<BITS>::constant(c, v)` — same reason, same shape.
3. `LedgerRepr::from_limbs` on `Secp256k1Point` — internal invariant, above.
4. `entry()`'s two law checks (`arg_count == SLOTS`, no instruction before the
   last declare) — phase 2's, unchanged: both are properties of a built
   circuit, not of a type.

* The contract block (dmd, 2026-08-16)

dmd asked what happens if contracts are defined as =impl=s of their state
that derive the circuit methods, and how far that hurts the tooling. The
answer split cleanly in two, and only one half survived contact with the
code.

** THE QUESTION THAT DECIDED IT: what constitutes a contract?

Before this, nothing did. A contract was a Rust MODULE by convention;
=#[circuit]= generated a nullary =pub fn deposit() -> Compiled3= and each
circuit compiled itself. The only statement anywhere of which circuits exist
was =support::circuits()= — 170 hand-written entries in a TEST-support
module, feeding both snapshots, the dump instrument and the adversarial
suite — and *nothing asserted it was complete*. 156 =#[circuit]= attributes
against 170 entries (the gap is the =entry()=-built families), and a circuit
added and not listed is covered by nothing at all.

Meanwhile the CALLER side has had the answer since M12: =#[interface] pub
trait SignetSigner= IS a contract's circuit set — order-significant, frozen
in =interface-schema.txt=, checked against the callee's artifact. So we knew
what circuits constituted a contract only when the contract was someone
else's.

=#[contract]= closes that: =KernelTokens::CIRCUITS= is =[(name, fn() ->
Compiled3); N]= in declaration order, derived from the file.

** THE BLOCK YES, THE RECEIVER NO

=&mut self= was declined, and the reasons are worth keeping because they are
about this eDSL rather than about taste:

- A contract's state is a LAYOUT, not a value. =#[derive(Ledger)]= makes
  declaration order the field index; a read is a transcript gate and a write
  is an Impact op. =&mut self= says "I own mutable data", and a Rust
  programmer will reasonably try =self.counter += 1= or branch on a read.
  Neither exists — a circuit does not branch. The =c: &mut Circuit3= in
  every signature is a standing reminder of which of the two you are doing.
- The borrow checker says no, or says yes at a price. =self.balances= and the
  circuit cannot both be =&mut=-borrowed through sibling fields, so the
  handles would have to be methods returning a borrowing view — workable —
  or the circuit goes behind a =RefCell=, which converts a borrow ERROR into
  a runtime panic. That is against the standing compile-errors-over-panics
  rule.
- Composability gets worse where it matters most. Every gadget below the
  contract takes =&mut Circuit3=: all of =minocrab-ledger=,
  =minocrab_std::v3::kernel=, and =common.rs= — which four vault forks share
  and which therefore cannot be a method of any one contract. A =&mut self=
  method would call =kernel::mint_shielded(self.circuit(), ..)=, so the
  codebase would gain a SECOND calling convention, one commit after this
  session collapsed six guard spellings into two.

So the methods are ASSOCIATED FUNCTIONS taking =c=, and a =self= parameter is
a compile error carrying that reason.

** As built

=#[contract]= on an inherent =impl=. Each =#[circuit]= inside expands exactly
as on a free function — same argument struct, same labels, same disclosure
declaration — with one structural difference forced by rustc: the generated
set-equality test is a =mod=, and a =mod= cannot live inside an =impl=, so
=circuit::expand= was split into =Expansion { entry, tests }= and the tests
are emitted BESIDE the block. They name the constructor through the contract
(=super::KernelTokens::deposit=), which is why =expand_in= takes the owner.

FIRST CONTRACT PORTED: =kernel_tokens=, all 24 circuits, chosen because its
differential is instruction-for-instruction so the gate is the strongest in
the tree. =support::circuits()= now DERIVES those 24 entries from
=KernelTokens::CIRCUITS= instead of listing them, and the differential gained
=every_exported_circuit_is_in_the_differential=, which compares FUNCTION
POINTERS (the two sides name circuits differently — compactc's =sMergeCoin=
against our =s_merge_coin= — so a count would pass while two entries
silently swapped).

ZERO MOVEMENT: row_snapshot and interface_snapshot bit-identical, the
instruction-for-instruction differential unchanged, =cargo test --workspace=
green. One SOURCE reorder was needed and no table changed: the derived order
is declaration order, and =s_receive_unshielded= was declared after the pair
that follows it in the fixture, so the function moved up twelve lines.

** REMAINING, and why it is not "just roll it out"

Five modules have a =#[derive(Ledger)]= state type (=adts=, =bounded=,
=erc20_vault=, =erc20_vault_modern=, =kernel_tokens=). The rest — including
=test_caller=, =xcall=, =events=, =hashing= — declare their ledger fields as
raw index constants (=pub const INITIALISED: u8 = 6;=), so they have no type
to hang an =impl= on. Giving them one is a real change (it moves the field
indices into the derive), not a mechanical wrap, and it should be done per
contract with its own gate rather than in one sweep.
