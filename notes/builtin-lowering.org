* 1. Value representation (flatten-datatypes)

=flatten-datatypes= (=compiler/circuit-passes/flatten-datatypes.ss=) maps
every Compact type to a flat list of circuit slots ("primitive types") plus a
parallel list of FAB *alignment atoms*. All later passes work slot-wise;
aggregates never exist at the ZKIR level.

Field parameters (=compiler/field.ss:36=, =compiler/langs.ss:60-68=):

** Bytes<N> limb layout — THE critical convention

=Bytes<N>= splits into ceil(N/31) limbs. Limb order in the flattened slot
list is *most-significant chunk first*; the partial chunk (N mod 31 bytes) is
the first slot. Within a limb, bytes are *little-endian* (byte 0 of the
chunk is the least significant). So:

- =Bytes<32>= = 2 slots: =[hi, lo]= where =hi= = byte 31 (one byte,
  constrained to 8 bits) and =lo= = bytes 0..30 as a little-endian integer
  (constrained to 248 bits).
- =Bytes<64>= = 3 slots: =[bytes 62..63 (16 bits), bytes 31..61 (248 bits),
  bytes 0..30 (248 bits)]=.
- =Bytes<N≤31>= = 1 slot.

Verified: a =Bytes<32>= circuit argument compiles to
=constrain_bits(arg0, 8); constrain_bits(arg1, 248)= (probe =degrade= below,
and =corpus/zkir/compact/examples/tiny/zkir/set.zkir= where the witnessed
=Bytes<32>= secret key gets =private_input=+=constrain_bits 8= then
=private_input=+=constrain_bits 248=); a =Bytes<64>= argument gets
=constrain_bits 16/248/248=. The Rust mirror is
=FromFieldRepr for [u8; 32]= (=transient-crypto/src/repr.rs:110-129=):
=repr[0]= = byte 31, =repr[1]= = bytes 0..31 LE — field_vec order [hi, lo].

Literal bytevectors flatten with the same convention: chunks of 31 bytes
from the string start, each read =little=-endian, accumulated so the
low chunk lands in the *last* slot (flatten-datatypes.ss:560-572).

** FAB Alignment atoms

Alignment lists attached to types are per-*source-atom*, not per-slot: one
=(abytes N)= atom covers all ceil(N/31) slots of a =Bytes<N>=. JSON form
(v2 =alignment->json=, print-zkir.ss:112-123) matches serde of
=base_crypto::fab::AlignmentAtom= (=base-crypto/src/fab/encoding.rs:639-650=):

: {"tag": "atom", "value": {"tag": "bytes", "length": N}}
: {"tag": "atom", "value": {"tag": "field"}}
: {"tag": "atom", "value": {"tag": "compress"}}

In v3, =anative= atoms are pseudo-atoms the ledger doesn't know; before any
hash they are expanded by =circuit-alignment-for=
(=zkir-v3-passes/reduce-to-zkir.ss:37-91=) into real atoms plus an =encode=
instruction: JubjubScalar → 1×=(afield)=; JubjubPoint → =(afield) (afield)=
(x,y); Secp256k1Base/Scalar → =(abytes 24) (abytes 8)= (2 limbs,
midnight-circuits public-input encoding; which bytes go in which limb:
UNVERIFIED, defined by =midnight-zk-stdlib= =MultiEmulationParams=);
Secp256k1Point → =(abytes 24) (abytes 8) (abytes 24) (abytes 8) (afield)=
(x, y, is-identity flag). v3 =Encode= output counts documented in
=zkir-v3/src/ir.rs:360-387=; note Encode(Bytes32) is =[low, high]= —
opposite of Compact's =[hi, lo]= slot order (=zkir-v3/src/ir_instructions/encode.rs:53-64=),
but Compact never encodes Bytes32 (only =anative= atoms reach =encode=).

** v2 vs v3 program shape

v2 (=print-zkir.ss=): implicit slot numbering. Arguments occupy slots
0..num_inputs−1; each output-producing instruction appends slots. Literals
via =load_imm= are hash-consed per circuit (one load per distinct constant;
print-zkir.ss:248-257). Argument slots get type constraints first
(=constrain-type=, print-zkir.ss:124-147), then body, then one
={"op":"output","var":i}= per result slot.

v3 (=reduce-to-zkir.ss= + =print-zkir-v3.ss=): named SSA variables
(="%p.0"=), typed =inputs= (e.g. ="Scalar<BLS12-381>"=, ="Point<Secp256k1>"=
— =type->string= reduce-to-zkir.ss:686-693), immediates inline as ="0x01"=,
one =output= instruction with =vals= list. Same constraint policy
(=emit-constraints-for= reduce-to-zkir.ss:640-667).

** Input type constraints (both versions)

For every =tunsigned max= slot entering the circuit (argument, witness
return, public input) — print-zkir.ss:124-147 / reduce-to-zkir.ss:640-667:
- max = 0 → =constrain_eq(x, 0)=
- max = 1 → =constrain_to_boolean=
- max = 2^k − 1 → =constrain_bits(x, k)=
- otherwise → =less_than(x, max+1, bits)= + =assert=, with
  bits = 2·⌈(integer-length(max+1)+1)/2⌉... precisely
  =(* 2 (quotient (+ (integer-length (+ 1 max)) 1) 2))= (even, for Plonk).
=Field=, opaque, and point slots get no constraint.

* 2. transientHash<T>

=transient_hash= (Poseidon over Fr; =transient-crypto/src/hash.rs:76=), one
instruction, one output slot. Inputs = the flattened slots of T in order; no
alignment operand. Handler: print-zkir.ss:154-157 (v2),
reduce-to-zkir.ss:219-221 (v3).

Verified (probe =thash=, =transientHash<Vector<2,Field>>(v)=):
: { "op": "transient_hash", "inputs": [0, 1] }   → 1 result slot

transientCommit<T>(value, rand): same gate with the *rand moved to the
front*: =transient_hash([rand, ...value-slots])= (print-zkir.ss:201-208,
reduce-to-zkir.ss:213-218).

* 3. persistentHash<T>

=persistent_hash= (SHA-256 of the FAB binary repr;
=base-crypto/src/hash.rs:93=, VM: =zkir/src/ir_vm.rs:410-424= parses inputs
against the alignment, byte-serializes, hashes). Operands: =alignment= = the
alignment-atom list of T (one atom per source atom, see §1), =inputs= = T's
flattened slots. v2 output: *2 new slots* =[hi, lo]= of the =Bytes<32>=
digest (memory.extend(hash.field_vec())). Handler print-zkir.ss:223-231.

v3: =persistent_hash= produces one *Bytes32-typed* value, which is
immediately split for Compact with =bytes32_into_low_high= (outputs =(low,
high)=; =zkir-v3/src/ir.rs:637-646=); the compiler binds result slots [hi,lo]
from it (reduce-to-zkir.ss:195-204).

** Worked example: persistentHash of a struct (v2, verified output)

#+begin_src compact
struct Pair { x: Field; y: Uint<16>; }
export circuit hashStruct(p: Pair): Bytes<32> {
  dummy.increment(1);
  return disclose(persistentHash<Pair>(p));
}
#+end_src

bytes). Same circuit under =--feature-zkir-v3=:

* 4. persistentCommit<T>(value, rand: Bytes<32>)

Lowered to a single =persistent_hash= whose preimage is *rand first, then
value*: alignment = =(abytes 32)= consed onto T's atoms, inputs =
=[rand_hi, rand_lo, ...value-slots]= (print-zkir.ss:209-222,
reduce-to-zkir.ss:180-194). Runtime mirror: =persistent_commit= hashes
opening ++ value (=base-crypto/src/hash.rs:97=).

Verified (probe =commit=, =persistentCommit<Field>(v, r)=; v=slot0,
r=slots1,2):
: { "op": "persistent_hash",
:   "alignment": [ {..bytes 32..}, {..field..} ],
:   "inputs": [1, 2, 0] }                        → slots 8,9 = [hi, lo]

* 5. degradeToTransient / upgradeFromTransient

Runtime semantics (=transient-crypto/src/hash.rs:64-73=):
=degrade_to_transient(h) = h.field_vec()[1]= — i.e. *the low limb* (bytes
0..30 LE, byte 31 discarded). =upgrade_from_transient(f)= = low 31 bytes of
f, byte 31 = 0 (top ~7 bits of the field element are *dropped*).

degradeToTransient(b): *zero instructions*. v2 rebinds the result to b's
second slot (print-zkir.ss:158-159). v3 emits a (free) =copy= of the low
slot (reduce-to-zkir.ss:129-130).

** Worked example (verified, v2 and v3)

#+begin_src compact
export circuit degrade(b: Bytes<32>): Field { dummy.increment(1); return disclose(degradeToTransient(b)); }
export circuit upgrade(f: Field): Bytes<32> { dummy.increment(1); return disclose(upgradeFromTransient(f)); }
#+end_src

v2 =degrade= (b = slots 0,1):
#+begin_example
{ "op": "constrain_bits", "var": 0, "bits": 8 }    ; b hi limb
{ "op": "constrain_bits", "var": 1, "bits": 248 }  ; b lo limb
...ledger preamble...
{ "op": "output", "var": 1 }                       ; result IS the lo limb
#+end_example

v2 =upgrade= (f = slot 0; note slot 3 is the hash-consed =load_imm "00"=
already emitted for the ledger preamble):
#+begin_example
{ "op": "div_mod_power_of_two", "var": 0, "bits": 248 }  ; → slot 6 = f>>248 (dropped),
                                                          ;   slot 7 = f mod 2^248
{ "op": "output", "var": 3 }                              ; hi := literal 0
{ "op": "output", "var": 7 }                              ; lo := f mod 2^248
#+end_example

(v2 handler print-zkir.ss:160-165; div_mod output order quotient-then-
remainder per =zkir/src/ir.rs:405-413=.) v3 (reduce-to-zkir.ss:222-228):
: { "op": "copy", "output": "%t.1", "val": "0x00" }
: { "op": "div_mod_power_of_two", "outputs": ["%tmp.2", "%t.3"], "val": "%f.0", "bits": 248 }
: { "op": "output", "vals": ["%t.1", "%t.3"] }

* 6. pad(n, "s") and string literals

Both are compile-time byte-vector literals — no dedicated instruction.
="s"= → UTF-8 bytes, type =Bytes<len>= (=compiler/lparser-to-lsrc.ss:160-166=);
=pad(n, "s")= → the same right-padded with 0x00 *at the end* (high bytes)
to length n (lparser-to-lsrc.ss:167-183). The literal then flattens per §1
and each needed limb becomes a =load_imm=.

=load_imm= immediate encoding (print-zkir.ss:248-269): hex string of the
integer's bytes *least-significant byte first* (=integer->le-bytes= +
=le-bytes->hex=); negative values get a leading "-". So byte i of a string
lands at hex chars [2i, 2i+1]: =pad(32,"abc")= → lo limb
=load_imm "616263"= (= integer 0x636261), hi limb = literal 0. Verified in
probe =padtest= and in tiny =set.zkir= (="6C617265733A74696E793A706B3A"= =
"lares:tiny:pk:").

* 7. default<T>

Compile-time, per flatten-datatypes.ss:252-305 (=default= Rhs):
- Boolean/Field/Uint/enum/opaque → literal 0
- =Bytes<N>= / contract → ceil(N/31) zero limbs
- Vector/tuple/struct → recursive
- =JubjubPoint= v2 → 2 literals =(0, 1)= — the twisted-Edwards identity
  (print-zkir.ss:705-708); v3 → =from_coordinates(0, 1)=
  (reduce-to-zkir.ss:807-810)
- =Secp256k1Point= (v3) → generator·0 = identity, built as
  =into_bytes32(0)= → =from_bytes32 Scalar<Secp256k1>= → =ec_mul_generator=
  (reduce-to-zkir.ss:811-818; verified in probe =ethAddr= via the
  =pk != default<Secp256k1Point>= assert).
stdlib =some/none/left/right= are therefore zero-cost constructors: probe
=maybeStuff= (build =some(v)=, =none()=, select on =is_some=) compiled to
just =output var 0=.

* 8. Casts

Cast dispatch is in =infer-types.ss:1809-1937=; =safe-cast= (provably
value-preserving) is erased by drop-safe-casts. What survives to ZKIR:

| source cast                          | v2 instructions                              | v3 instructions |
|--------------------------------------+----------------------------------------------+-----------------|
| =Uint<N> as Field=                   | nothing (safe-cast)                          | nothing         |
| =Field as Uint<N>= (=cast-from-field=) | §1 constraint on the same slot (=constrain_bits= / =less_than=+=assert=); no new slot (print-zkir.ss:616-622) | same + a =copy= (reduce-to-zkir.ss:977-993) |
| =Uint<M> as Uint<N>=, N<M (=downcast-unsigned=) | §1 constraint, no new slot (print-zkir.ss:606-612) | same + =copy= |
| =Field as JubjubScalar= (=cast-to-field=) | =copy= — no range check! JubjubScalar is a plain Fr slot in v2 (print-zkir.ss:817-818) | =jubjub_scalar_from_native= (mod-r reduction; reduce-to-zkir.ss:968-976) |
| =JubjubScalar as Field=              | =copy=                                       | =encode=        |
| =Bytes<32> as Field= (=bytes->field=) | =reconstitute_field(divisor=hi, modulus=lo, bits=248)= — 1 slot; overflow-constrained by the gate (print-zkir.ss:795-802; VM ir_vm.rs:371-398). For =Bytes<N>= N>62: extra hi limbs get ====0=-assert chains first (flatten-datatypes.ss:381-417) | same op, named form (reduce-to-zkir.ss:934-953) |
| =Field/Uint as Bytes<N>= (=field->bytes=) | N≤31: =constrain_bits(x, 8N)=, result slot = x, hi limbs literal 0. N>31 (i.e. 32..62): =div_mod_power_of_two(x, 248)= → 2 slots [hi=quo, lo=mod] (print-zkir.ss:721-734) | same (reduce-to-zkir.ss:820-842) |
| =Bytes<32> as Secp256k1Scalar/Base= (v3 only) | n/a | =bytes32_from_low_high(lo, hi)= → =from_bytes32 "Scalar<Secp256k1>"= (mod-n reduce; reduce-to-zkir.ss:936-944) |
| =Secp256k1Base/Scalar as Bytes<32>= (v3) | n/a | =into_bytes32= → =bytes32_into_low_high= (reduce-to-zkir.ss:826-831) |
| =Bytes<N> as Vector<N,Uint<8>>= (=bytes->vector=) | per limb, starting from the *lo* limb: chain of =div_mod_power_of_two(limb, 8)= — remainder = byte i, quotient feeds the next; the 31st byte of a limb is the final quotient (bound directly, no gate) (print-zkir.ss:709-720; flatten :434-447) | same, with =copy= for the last byte (reduce-to-zkir.ss:848-856) |
| =Vector<N,Uint<8>> as Bytes<N>= (=vector->bytes=) | per 31-byte chunk: right-fold of =reconstitute_field(divisor=rest, modulus=v[i], bits=8)= — v[0] least significant (print-zkir.ss:803-816) | same (reduce-to-zkir.ss:954-967) |
| =Boolean as Uint/Field=, enum casts  | select/copy/constraint per replace-enums.ss:33-58, infer-types.ss:1855-1917 | same |

byte indexing =b[i]= (=bytes-ref=): 2 gates —
=div_mod_power_of_two(limb, 8·(i mod 31))= then =div_mod_power_of_two(quo, 8)=,
result = 2nd output of the 2nd gate (print-zkir.ss:784-790).

* 9. Uint arithmetic and comparisons

Types carry *max values*, not widths (=tunsigned max=). Rules
(=infer-types.ss:660-745=):
- =+=, =*=: plain field =add= / =mul=, result type =Uint<maxa+maxb>= resp.
  =Uint<maxa·maxb>=; error if result max > 2^248−1 ("cast to Field"). No
  gates beyond add/mul — *no overflow check at the op itself*; the check
  happens only when the value is later downcast (assignment to a declared
  =Uint<N>= inserts =downcast-unsigned= → §1 constraint).
  REFINED (2026-08-16, artifact evidence): the downcast check does NOT
  extend to a cast in ARGUMENT position. The vault writes =amount as
  Uint<64>= at all four settle mints (claim/completeWithdraw/refund/
  completeSwap) on a value locally bounded only to < 2^128, and the
  artifacts contain no 64-bit constraint between decode and mint — the only
  64-bit op in each is the =initialized= counter guard. The contract is
  safe because every request circuit bounds its amounts to ≤ u64::MAX
  before the record enters the map (erc20-vault.compact:263/431/801-802) —
  a whole-contract argument compactc neither makes nor checks. See
  notes/api-safety-survey.org §B4.
  THE REFINEMENT WITHDRAWN (2026-08-28, notes/compact-findings.org §1):
  the downcast check DOES cover argument position — the 2026-08-16 scan
  missed its GUARDED spelling. Straight-line, the cast is
  =constrain_bits N=; inside a conditional branch it lowers to
  =cond_select(branch, ·, val)= → =less_than(·, 2^N, bits = source
  width)= → guarded =assert= — the comparison runs at the SOURCE's
  width, which is why a "64-bit op" search found nothing. Probe-verified
  under 0.33.0-rc.2 and 0.34.0; the four settle mints all carry their
  checks (claim/completeSwap as constrain_bits, completeWithdraw/refund
  as the guarded shape). The §1 rule therefore reads: downcast inserts
  the range check in EVERY position, constrain-style straight-line,
  select/less_than/assert-style under a guard.
- =-=: inserts an explicit guard *before* the subtraction:
  =assert(a >= b, "result of subtraction would be negative")= with
  bits = max(1, intlen(max(maxa,maxb))), then field subtraction lowered as
  =neg(b)= + =add(a, neg)= (print-zkir.ss:774-777). Result type =Uint<maxa>=.
- =<=: =less_than(a, b, bits)= with bits = max(1, intlen(larger max))
  (infer-types.ss:753-771) — note: *not* rounded up to even here (the even
  rounding is only in §1 constrain-type); verified =Uint<64>= compare emits
  bits=64, =Uint<0..1000>= constrain emits =less_than= bits=10.

* 14. assert(cond, "message")

The message is *dropped from ZKIR*: v2 ={"op":"assert","cond":i}=

* Consequences for the MinoCrab eDSL typed-value layer

- The typed-value layer's unit is the *slot vector + alignment-atom vector*
  pair (exactly flatten-datatypes' =(ty (alignment...) (primitive-type...))=).
  Every aggregate op (==, select, hashing, witness binding, returns) is
  defined slot-wise; get the =[hi, lo]= Bytes limb order and the
  hi-limb-first convention right once, in one place.
- Uint types must carry *max values* (not bit widths): result-max
  arithmetic (+ → sum, * → product, − → left max), the 4 constrain shapes,
  and the even-bits rule for the =less_than= constrain path are all
  max-value-driven. =Uint<N>= is just max = 2^N−1.
- Several builtins are zero-instruction re-bindings (degradeToTransient,
  jubjubPointX/Y v2, constructJubjubPoint v2, constant Vector indexing,
  struct/tuple construction and field access, some/none/left/right) —
  the eDSL IR needs a notion of aliasing an existing slot.
- Literal pool: v2 hash-conses =load_imm= per circuit and *shares them with
  the ledger-op preamble* (e.g. upgrade's hi-limb 0 reuses the preamble's
  literal 0) — byte-exact differential tests must reproduce literal reuse
  and emission order, not just per-op templates.
- Effects survive dead-value elimination: the subtraction guard assert
  stays when the difference is discarded; add/neg get dropped. Differential
  tests should cover unused-result cases.
- v2 vs v3 differ structurally (slot indices vs named typed SSA; Jubjub
  2-slot vs typed value; =Field as JubjubScalar= copy vs mod-reduction!),
  so the eDSL backend needs per-version lowering templates behind one
  typed IR.
