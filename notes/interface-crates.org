#+title: M12 interface crates: design of record

Opus design survey 2026-08-15 (full text in session transcript; this
file carries every decision + enough detail to implement). NEAR-style
interface crates over the M5 desugar; cargo as Compact's package
manager; static interfaces (dmd-approved).

* Ground truth the design rests on
- contract_call (minocrab-ledger/src/lib.rs:701-753) IS the whole M5
  desugar; M12 sits above it. Four call sites hand-flatten args +
  hand-write result-bit lists — that's what M12 deletes.
- ep_hash derivation FOUND: EntryPointBuf::ep_hash (onchain-state/src/
  state.rs:668-675) = persistent_commit(name, "midnight:entry-point"
  +12 zero bytes) = SHA256(opening ‖ name). Implement by CALLING
  upstream, never re-deriving. Limb split hi=byte31, lo=LE(0..31).
  Ledger acceptance: (addr, ep_hash, comm) match, structure.rs:2738.
- Compact already has the trait (export contract SignetSigner,
  Signet.compact:194) and compactc ships it as data: BOTH caller and
  callee contract-info.json carry fully typed circuit signatures; the
  .zkir carries input count + the constrain_* prefix (e.g.
  signBidirectional: 8,248,8,32,248,248,248,248) = the derived list.
- compactc's constraint table is ONE function (reduce-to-zkir.ss:
  640-667 emit-constraints-for): opaque/field/point → none; u0 →
  constrain_eq 0; u1 → constrain_to_boolean; 2^k−1 → constrain_bits k;
  other → less_than+assert. make-witness runs the SAME table over
  private inputs ⇒ argument constraints (CircuitArg::constrain) and
  result constraints (contract_call bit list) are ONE table currently
  duplicated by hand. Unifying = stage 1.
- Corpus census: only 2 non-2^k−1 Uint maxvals corpus-wide (test
  fixture, no zkir); Opaque 74 (reject in importer); structs dominated
  by ContractAddress/Either/Maybe/ShieldedCoinInfo (all have v3 types).

* Decisions
- #[interface] on a bodyless trait (one fn per callee circuit, typed
  with M9 leaves; no self; ALL params/results Public — passing
  cross-contract discloses, so CallArg/CallResult exist only at
  Public; private values must disclose() first, compiler-enforced).
  Expands (replacing the trait, #[circuit] precedent) to a struct +
  inherent impl: EntryPoint consts (name derived snake→lowerCamel,
  #[entry_point(name)] escape), at_field(index)/at(address)
  constructors (Callee::Field does a FRESH UNCACHED cell_read per
  call — xcall::call_twice proves compactc re-reads per site; caching
  would move rows), typed methods calling a new
  minocrab_ledger::call<A: CallArgs, R: CallResult>() over
  contract_call. Thinness rules hold: expansion contains no Circuit3
  call; codegen shared with circuit_arg.rs's impl_arg_traits.
- Visibility-generic derive mode: #[derive(CircuitArg)] on Ty<V: Vis3>
  emits CircuitArg at Private AND CallArg/CallResult at Public — one
  type serves callee (witness side) and caller.
- Ledger generalization: result_limb_bits &[Option<u32>] →
  &[LimbConstraint{Bits/Boolean/Zero/Bounded/None}] (Option<u32> can't
  express constrain_to_boolean). EntryPoint/ep_hash/ep_limbs beside it.
- comm layout falls out of the shared type's declaration order ⇒
  argument reorder/retype changes the Poseidon comm ⇒ ledger rejects ⇒
  SEMVER-MAJOR BY CONSTRUCTION. Mechanical rule: schema snapshot
  changed = major.
- ContractAddress<V> = newtype over B32<V> in minocrab-std (Compact's
  own struct, 164 corpus occurrences). Interface crates NEVER contain
  addresses; deployments pin via sealed ledger cell (at_field) or pass
  as data (at()); optional deployments module = plain [u8;32] consts,
  off-circuit only.
- Artifact agreement: interface crate commits contract-info.json +
  distilled hash-pinned pin.json (zkir sha256, input counts, constraint
  prefixes, do_comm flag, compiler versions); full-.zkir check opt-in
  via env/feature (offline-first; hash-pinned FETCH rejected). Checker
  in new crate minocrab-abi: entry point exists + proof:true (real
  check — whole Signet module is proof:false), typed tree ≡ derived
  atoms/prims, result constraints ≡, do_comm true, zkir constraint
  prefix slot-for-slot when available, digests match. Mutation test
  proves the checker bites. Frozen interface-schema snapshot (ep name,
  ep_hash hex, per-slot widths/constraints) = the published ABI; its
  diff IS the semver decision.
- Importer: CLI crate minocrab-interface-gen (NOT build.rs — generated
  source must be readable/reviewable/docs.rs-able; --check regenerates
  and diffs, the codegen snapshot guard). Type mapping table in the
  full design; highlights: Bytes≤31→Bytes<n>, 32→B32, >32→BytesN,
  Uint 2^k−1→Uint<k>, other maxval → error unless --allow-bounded
  (no corpus zkir evidence), Boolean→Bool, Vector→[T;n],
  Maybe/Either/ContractAddress matched by name+shape, other structs →
  generated #[derive(CircuitArg)] (deduped by name; same name +
  different shape = error), Alias → pub type, Enum → u8 + named
  consts, Opaque → error, Tuple → () / Rust tuple. Can also read the
  CALLER's contracts[] entry (--from-caller).
- Export direction (own contracts): the interface crate is the LOWER
  crate — the contract crate depends on it and uses its types in its
  circuits (one definition of every shared type); a
  contract_matches_its_interface test compares each circuit's built
  IrSource against the trait schema. (Rejected: feature-gated subset
  of the contract crate — heavy deps, semver coupled to impl churn.)
- Session defaults on the design's open questions (dmd may override):
  interface crates live under crates/ in-workspace; git/path
  consumption suffices for M12 (crates.io publication later); pinning
  form as above confirmed; signet-protocol crate split (record types /
  request-id / ECDSA out of contracts/src/signet.rs) noted as
  FOLLOW-ON, not M12 scope — stage 4 moves only Notification +
  construct_notification_v1 into the interface crate.

* Honest limits (README must carry #1)
1. The CIRCUIT binds neither ep nor arg types (ep limbs are witnesses
   — why callOnce/callEmit share a circuit; arg limbs are opaque field
   elements in the comm). The typing protects the developer and tx
   builder; the VERIFIER's protection is the ledger's (addr, ep, comm)
   match. State this in the README section.
2. Static interfaces; call_dynamic representable but deliberately not
   built.
3. Callee upgrades: VK is versioned per (address, ep); same-signature
   redeploys are invisible (correct); signature changes under the same
   name break at validation; agreement test catches on re-pin.
   Binding artifact→deployed address needs the VK (keygen) — out of
   scope, sketched as verify_deployment for later.
4. No promises/callbacks/failure channel/gas control/value-on-call;
   results are prover-supplied ⇒ tx builder runs the callee FIRST
   (off-circuit orchestration = future work; schema() gives builders
   the layout).
5. Field/point result slots carry no constraint (compactc's own rule)
   — bounded only by the comm; stated, not fixed.

bit-identical, all suites green, workspace release build clean;
review-queue line per stage)

3. #[interface] + visibility-generic derive; re-express stage-2

* As built — stage 1 (2026-08-15)
The ABI table, =EntryPoint=, and the split of =CircuitArg= into a schema
half and a materialization half. NO circuit touched: row_snapshot and
interface_snapshot bit-identical, all differential suites green,
=cargo test --workspace --release= clean (54 test binaries).

** WHERE THE TABLE LIVES, and why not minocrab-std
=minocrab::v3::abi= (crates/minocrab/src/v3/abi.rs), not minocrab-std.
=LimbConstraint= is =contract_call='s parameter type and minocrab-ledger
is L2.5 — BELOW L3 (notes/architecture.org) — so a table in minocrab-std
would have inverted the layer map to save a file. minocrab (L2) owns
=Circuit3=, which is what the table lowers into, so it is the right home
and both L2.5 and L3 can name it. minocrab-std re-exports =Prim= /
=LimbConstraint= from =v3=, since that is where argument types are
written.

** =Prim= splits the unsigned case by REPRESENTATION
compactc dispatches on a raw =maxval=; a =Uint<248>='s maxval does not
fit a =u128=, so =Prim::Uint{bits}= carries the exponent of a
=2^bits − 1= bound (every typed leaf, every zkir-backed corpus artifact)
and =Prim::UintMax{maxval}= a literal bound that is not one less than a
power of two. =Prim::unsigned(maxval)= normalizes between them using
compactc's own predicate (=maxval & (maxval+1) == 0=), and a property
test over 4096 bounds asserts the partition is exactly compactc's. The
four branches of =emit-constraints-for= are then a total match:
opaque/field/point → None, bits 0 → Zero, bits 1 → Boolean, bits k →
Bits(k), else → Bounded{bound = maxval+1, bits = 2⌈log₄ bound⌉}. Six
unit tests, one per Scheme case plus the partition and the u128→Fr
conversion.

** TWO NEW =Circuit3= METHODS, for faithfulness not ergonomics
=assert_eq_imm= / =less_than_imm=: compactc writes =(constrain_eq
,var-name ,0)= and =(less_than ,tmp ,var-name ,(1+ nat) ,bits)= with the
bound as an INLINE operand, and =c.constant()= emits a =Copy= just to
name an immediate. Lowering Zero/Bounded through =c.constant= would have
made our stream differ from compactc's by an instruction per slot — in
the two cases M12 stage 4's slot-for-slot constraint-prefix check will
compare. The IR builder already took =impl Into<Arg>=; these just expose
it. Neither case is reachable from a typed leaf today, so nothing moved.

** =CircuitAbi= / =CircuitArg=: the schema is VISIBILITY-INDEPENDENT
=CircuitAbi{SLOTS, push_atoms, push_prims}= is implemented for every
=Vis3=; =CircuitArg: CircuitAbi= adds =declare= + =push_slots= at
=Private= only. This is the load-bearing shape for stages 2-3: the
caller's =CallArg=/=CallResult= (Public) will sit on the SAME
=CircuitAbi=, so one type describes both sides of a cross-contract call
and cannot describe them differently. =SLOTS= counts NATIVE SLOTS, which
is not the atom count (a =Bytes<32>= is one atom across two slots), so
=prims().len() == SLOTS= while =atoms()= is shorter.

** =constrain= IS NOW A PROVIDED METHOD — the parallel copy is gone
Every =CircuitArg= impl used to carry its own =constrain=. The trait now
provides it: zip =push_prims= against =push_slots=, run
=Prim::constraint().emit()=. An impl says WHAT its slots are and never
how they are constrained. The leaves' own =constrain_input= methods route
through the same table, so the two spellings cannot diverge either. Nine
hand-written impls across src and tests shed their =constrain= bodies.

*** THE ONE SEMANTIC CHANGE: =Uint<1>=
Under the old hand-written rule =Uint<1>= was =constrain_bits(1)=; under
compactc's table it is =constrain_to_boolean=. Verified zero-movement by
grep: no =Uint<1, ...>= exists anywhere in the workspace. Documented on
=Uint::constrain_input=. (=Bytes<N>= cannot reach it — =8N ≥ 8= — and
=Uint<0>= is rejected by the leaf's const assert.)

** =EntryPoint= CALLS upstream; the test sweeps the whole corpus
=minocrab_ledger::{EntryPoint, ep_hash, ep_limbs}=. =ep_hash= is
=EntryPointBuf::ep_hash= (midnight-onchain-state) and nothing else — a
reimplementation that agreed today would be a silent chain-split the day
upstream changed the domain separator. =EntryPoint= is a =&'static str=
newtype with a =const fn new=, because stage 3 puts these in generated
=const=s.
=crates/minocrab-ledger/tests/entry_point.rs= walks corpus/zkir, finds
312 =contract-info.json= artifacts carrying 618 DISTINCT circuit names,
and for each asserts (a) our hash == a freshly built =EntryPointBuf='s,
and (b) our hash == =persistent_commit(name, "midnight:entry-point" ‖
12 zero bytes)= with the separator spelled out by hand — so an upstream
change to the derivation fails loudly here rather than silently re-keying
every call. The =[hi, lo]= limb split is checked against the ledger's own
=field_repr= of the hash as a =Bytes<32>= =AlignedValue=.

** =contract_call= now takes =&[LimbConstraint]=
=&[Option<u32>]= could not express =constrain_to_boolean= or
=constrain_eq 0=. The one call site with a non-empty list
(xcontract_events =depositViaVault=, =Bytes<32>= return) became
=[Bits(8), Bits(248)]= — same instructions, same rows.

* As built — stage 2 (2026-08-15)
The typed call core and all four call sites through it. row_snapshot and
interface_snapshot bit-identical, all differential suites green (including
the three vault artifacts and their fork tests), workspace release suite
clean (54 test binaries).

** DEVIATION: =CircuitAbi= moved to minocrab (L2), and why it had to
Stage 1 put =CircuitAbi= in minocrab-std beside =CircuitArg=. Stage 2 needs
=minocrab_ledger::call<A: CallArgs, R: CallResult>= — the design's own
placement — and minocrab-ledger is L2.5, BELOW minocrab-std, so it cannot
name a trait defined there. Since =CallArg=/=CallResult= must share
=CircuitAbi= with =CircuitArg= (that sharing IS the design: one type
describes both sides of a call), the whole ABI vocabulary moved down into
=minocrab::v3::abi=, which is where the table already lived. minocrab-std
re-exports all of it from =v3=, so every existing spelling still works.
Consequence for the orphan rule: =impl CircuitAbi for [T; N]= and for =()=
now live with the trait; the matching =CircuitArg= half for arrays stays
with the leaves.

** SECOND DEVIATION: =Callee::Pinned= holds limbs, not =ContractAddress=
The design says =Pinned(ContractAddress<Public>)=. =ContractAddress= is a
newtype over =B32=, which is L3, and =Callee= is named by =call= in L2.5 —
same layering problem, no shared-vocabulary escape (an address type needs
=B32='s slot layout). So =Callee::Pinned([Wire3<FieldT, Public>; 2])= holds
the FAB limb pair, and every handle's =at(address: ContractAddress<Public>)=
constructor does the one-line conversion. The user-visible API is the
design's; only the enum payload differs.

** THE ORDERING PROBLEM NOBODY WROTE DOWN, and =Callee::pin=
compactc evaluates a call's RECEIVER before its argument expressions. Rust
evaluates the arguments before the call. Where an argument expression emits
instructions the two orders differ, and the public transcript is ORDERED, so
the difference is real — not cosmetic.
Three of the four call sites are unaffected (their argument expressions emit
nothing between the read and the call), so =Callee::Field= resolving inside
=call= reproduces compactc's stream exactly. The erc20-vault's is not: its
second argument is
=constructSignBidirectionalEventNotificationV1(kernel.self(), …)=, and
=kernel.self()= is a public-transcript read. For that shape =Callee::pin(c,
guard)= resolves the sealed-cell read at the point the port chooses — which
is where compactc puts it. All three vault artifacts use the same spelling.
This is the sort of thing that would have been found by a failing
differential; it was found by reading compactc's evaluation order first, and
the differentials then agreed.

** =call= names the entry point and does NOT bind it
=call(c, guard, callee, entry_point, args)=. The =entry_point= argument is
deliberately unused in-circuit: ep limbs are prover-supplied WITNESSES, so
the circuit cannot bind them (honest limit #1). What binds them is the
ledger's =(address, ep, comm)= match. Naming the entry point types the
developer's call and tells the transaction builder which circuit to run.
=xcall::call_once= and =xcall::call_emit= now go through DIFFERENT typed
methods and a new test asserts their SERIALIZED ZKIR is identical while
=ep_hash("deposit") != ep_hash("depositEmit")= — honest limit #1 as an
executable claim rather than a paragraph. (=call_emit= is deliberately NOT
added to =support::circuits=: it would add a row_snapshot entry for a
circuit proven byte-identical to one already there.)

** Everything the caller no longer writes down
Before: a flat =&[Wire3]= the caller hand-flattened in the callee's slot
order, and a hand-written result-constraint list. After: =CallArgs= (tuples
of =CallArg=, up to arity 12) flattens from the TYPES, and the result
constraints come from =R::prims()= through =Prim::constraint= — the same
table that constrains the callee's own arguments. A struct passed
cross-contract cannot be flattened in the wrong order, and a result's range
check cannot be forgotten, because neither is written.
=CallArg=/=CallResult= exist at =Public= ONLY. Passing a value
cross-contract discloses it (it enters the commitment the ledger matches),
so a private value must =disclose()= first and forgetting is a compile
error — the =CircuitOut= rule, for the same reason.

** New types, and where they went
- =minocrab::v3::abi=: =CircuitAbi=, =CallArg=, =CallArgs= (tuple impls
  0..=12), =CallResult=, plus the =()= and =[T; N]= impls.
- =minocrab_std::v3::call= (new file): the leaves as =CallArg=/=CallResult=
  at =Public=. Mechanical; the content is that they exist at =Public= only.
- =minocrab_std::v3::ContractAddress<V>= — a newtype over =B32<V>=, because
  a contract address and a hash are not interchangeable and stopping them
  being passed for each other is the interface layer's job. Its FAB shape IS
  the inner =Bytes<32>='s (Compact structs flatten), which is why introducing
  it moved nothing.
- =minocrab_ledger::{Callee, call}=.
- =minocrab_contracts::interfaces= — =SignetSigner=, =Token=, =XcallTarget=,
  =PaymentTarget=: the hand-written target for stage 3's =#[interface]=
  expansion. Each has =EntryPoint= consts derived from Compact names,
  =at_field= / =at= / =pin= constructors, and typed methods.
- =minocrab_contracts::signet::Notification= — the callee's
  =SignBidirectionalEventNotification=; =construct_notification_v1= now
  returns it instead of a =(version, payload)= tuple. Stage 4 moves both.

** The scenarios now carry REAL entry-point hashes
Four differential suites invented ep bytes (=b"ep:deposit"= etc.). All four
now derive them: =ep_hash("deposit")=, =("depositEmit")=, =("notify")=,
=("confirmRequest")=, =("signBidirectional")= — including the vault model's.
Preimage-only, as predicted: the ZKIR is unchanged and every suite stayed
green without any other edit. Nothing in any suite compares a preimage
against a corpus artifact's ep, so there was nothing to investigate.

** THE TRAIT IS THE COMPACT DECLARATION
#+begin_src rust
#[interface]
pub trait Token {
    fn deposit(amount: Uint<128, Public>, caller: ContractAddress<Public>) -> B32<Public>;
}
#+end_src
reads next to =contract Token { circuit deposit(amount: Uint<128>, caller:
ContractAddress): Bytes<32>; }=, which is the point of using a trait rather
than a macro over a struct: one bodyless item per circuit, typed, nothing to
get wrong. It is REPLACED (the =#[circuit]= precedent) by a handle struct
with =EntryPoint= consts, =at_field= / =at= / =pin= / =callee=, and one
typed method per circuit over =minocrab_ledger::call=.
Thinness holds: the expansion contains no =Circuit3= method call — =c= is
threaded to =call= and nothing else — and the unit test greps the expansion
for =c .= and =Circuit3 ::= exactly as the other three macros' do.

** THE ERROR THAT MATTERS MOST IS THE ONE ABOUT DEFAULTS
=reject_undisclosed= fires on TWO shapes, and the second is the one that
would have bitten: =fn f(amount: Uint<128>)= — because the leaf types
default their visibility to =Private=, so a parameter that merely omits
=Public= is private, and the natural spelling is the wrong one. Both
messages name =disclose()= and say why (a value passed cross-contract enters
the commitment the ledger matches in the clear). The check is SYNTACTIC —
does the written type mention =Private=, does it mention =Public= — because
the alternative is a trait-bound error pointing at generated code. Fourteen
rejections in all, each with its own span, each unit-tested: trait generics /
where-clause / supertraits / unsafe / auto / non-fn items; method bodies /
=self= / generics / where-clause / async / unsafe / const / extern /
variadic / pattern parameters; private-or-defaulted parameter and result
types; and both malformed spellings of =#[entry_point]=.

** VISIBILITY-GENERIC DERIVE: reconciled with M11 by GENERALIZING it
M11 stage 3 taught =#[derive(CircuitBorsh)]= to emit the argument family for
a =struct P<V: Vis3>= through a where-clause rather than a substitution —
=impl<V: Vis3> CircuitArg for P<V> where Uint<8, V>: CircuitArg, …= holds
exactly at =Private=, because that is where the leaf impls exist. Stage 3
moves that judgement into =circuit_arg::ArgBounds= and adds two more clauses,
so ONE declaration now yields: =CircuitAbi= everywhere (a schema is
visibility-independent), =CircuitArg=/=CircuitArgs= at =Private=, and
=CallArg=/=CallResult= at =Public=. =#[derive(CircuitArg)]= gained the same
mode (it previously had none, so =Notification<V: Vis3>= could not have been
derived at all), and =#[derive(CircuitBorsh)]= now calls
=ArgBounds::visibility_generic= instead of building its clauses inline —
still one code path, one more thing shared.

*** WHY THE CALL IMPLS ARE EMITTED ONLY IN VISIBILITY-GENERIC MODE
First attempt emitted them always, with field bounds. It does not compile: a
plain struct's impl has no generic parameters, and rustc checks a concrete
impl's where-clause at the definition — so an all-=Private= struct would not
merely fail to be a =CallArg=, it would fail to BUILD. Emitting them only
where the bound can be conditional is both the fix and what the design said.
Consequence, documented on =ArgBounds::call=: a type meant to cross a
contract boundary is written =Ty<V: Vis3>=, which is how the corpus's shared
records are written anyway.

*** The proof it works: =Notification=
=signet::Notification<V>= was stage 2's hand-written =CircuitAbi= +
=CallArg= (27 lines). It is now =#[derive(Clone, CircuitArg)]= on the struct
and nothing else, and the vault's three artifacts are unchanged.

** =EntryPoint= consts, derived
=sign_bidirectional= → const =SIGN_BIDIRECTIONAL= = =EntryPoint::new(
"signBidirectional")=, i.e. SCREAMING_SNAKE for the const and the M9
=snake_case → lowerCamelCase= rule (shared with =#[derive(CircuitArg)]=) for
the Compact name. =#[entry_point(name = "…")]= overrides the name where the
two disagree; none of the four corpus interfaces needs it, which is itself
evidence the mechanical rule is right.
