#+title: M6 baseline benchmark: erc20-vault + Signet singleton, MinoCrab vs compactc

* Methodology
- Targets: all 9 erc20-vault circuits + the Signet singleton's 3
  (signet-contract.compact). Both artifact sets at the same pinned
  versions: compactc 0.33.0-rc.2 goldens from =corpus/zkir=, MinoCrab
  artifacts built in-process from =crates/minocrab-contracts=.
- Same statement per circuit: each measurement proves the *same*
  =ProofPreimage=, dumped by the differential tests (which first verify
  PI-equality of both artifacts on it — the M3 harness). So the numbers
  compare circuits proving identical statements, not merely similar ones.
- Harness: =crates/minocrab-bench= via =./bench.sh= (or =nix run .#bench=).
  One subprocess per circuit × side; peak RSS is =getrusage= of that
  process. Keygen/prove/verify through midnight's own =Zkir= impl
  (midnight-zkir-v3 rev 04c9c5d, the rev our compactc's bundled zkir-v3
  binary is built from); SRS params hash-verified into
  =~/.cache/midnight/zk-params= and warmed before timing.
- Outputs: =target/bench/results.json=, =report.md=, and per-region
  MinoCrab cost profiles under =profiles/= (minocrab-sim's v3 profiler).
- Caveats: prove time is the median of 3 in-process iterations per cell
  (MINOCRAB_PROVE_ITERS); keygen is single-shot. Keygen/prove timings
  include re-reading the cached SRS file from disk (identical for both
  sides); corpus side has no region breakdown (no span info in compactc
  output).

Findings:
- BASELINE PARITY CONFIRMED where designed: rows within ±0.7% on 7/9
  vault circuits (the lowering mirrors compactc's op sequences), and
  the wall-clock deltas there are noise-level (median-of-3 still swings
  a few % — initialize's +13.7% prove is 0.3s on a 2.3s cell). This is
  the correctness-preservation evidence the milestone wanted.
- MinoCrab strictly better on rows where compactc pays extra
  div_mod/reconstitute byte-repacking: refund -12.2%, completeSwap
  -14.6%, singleton circuits -53..-55% (their emit path explodes and
  rebuilds bytes twice — respond 270 div_mod vs our 120).
- k strictly lower on 5 circuits → ~half prove time and RAM there:
  claim + completeWithdraw (16 vs 17: near-equal rows sit just under
  2^16 for us, just over for them) and all 3 singleton circuits (15 vs
  16). Measured: completeWithdraw -52% prove / -43% RSS, respond -47% /
  -50%.
- Proof sizes identical per circuit (same proof system); verify times
  all ~10-20ms.
- Wall-clock methodology note: single-shot proves swing up to 3x with
  machine state (one k=16 cell: 22s quiet vs 103s loaded) — hence
  median-of-3 and k/rows/RSS as primary metrics.

* Ranked M7 optimisation targets (region-attributed profiles, profiles/)
Region spans landed with this run (helpers annotate all 12 circuits;
innermost region wins; regenerate with minocrab-bench --profiles — no
proving needed). Instruction shares below; div_mod_power_of_two +
reconstitute_field chains dominate every top region.
1. reverse_bytes32 in the ECDSA attestation verify: "signet:
   attestation verify" is 198 instructions (180 of them div_mod +
   reconstitute from the two byte-order reversals) — 45% of claim, 30%
   of refund/completeSwap, in every settle circuit. A byte-order-aware
   scalar import (fold big-endian directly instead of
   explode→reverse→rebuild) removes ~all of it.
2. "abi words" (calldata word build/parse): 18-44% everywhere —
   swap 288 instr (44%), completeSwap 256 (39%), refund 211 (30%).
   Same fix shape: fold bytes with mul-add chains instead of full
   explode/rebuild round-trips (the ×15 add/mul fold in
   abi_word_to_uint128 is already the cheap form — the explode side
   is the cost).
3. "signet: notification" (160 instr: 123 reconstitute) — 44% of
   deposit, 37% of withdraw, 25% of swap — and the singleton's "event
   serialize + emit" (98% of respond: 278 reconstitute + 120 div_mod).
   Batched/wider-limb serializer output attacks both.
4. k-boundary circuits: refund (85,185 rows) and completeSwap (89,300)
   at k=17 need ~25% row cuts to reach k=16 (→ ~half RAM/prove);
   targets 1+2 are together ~60-70% of their instructions, so the
   headroom is there. Protect claim (64,985) and completeWithdraw
   (64,791) sitting just under 2^16 while optimising.

* M7 pass 1 (2026-08-15): native-instruction byte plumbing
The baseline's targets 1-3 all turned out to be the same defect: the
ports mirrored compactc's Compact-stdlib byte handling (explode limbs
into bytes with div_mod chains, rebuild with reconstitute chains), but
ZKIR v3 has cheaper native forms. Measured row costs
(crates/minocrab-sim/examples/opcost.rs, deterministic):
- div_mod_power_of_two: ~90-147 rows EACH (large fixed floor; cost is
  independent of split position, weakly dependent on operand width —
  tree-splitting does not help). A 31-byte explode is ~4,400 rows.
- reconstitute_field: ~12 rows. mul/add: ~3. The rebuild side was
  never the problem; byte DECOMPOSITION is the entire cost.
- Native ReverseBytes (Bytes<32>): ~150 rows — replaces a ~4,600-row
  explode/reverse/rebuild round-trip.

Rewrites (all value-preserving, so PI-equality holds — all 13
differential suites green unchanged):
- signet::reverse_bytes32 → native ReverseBytes (to_typed / reverse /
  from_typed). Kills the 3 reversal round-trips per attestation verify
  (r, s import) and hash_to_secp256k1_scalar's (z) in minocrab-std.
- evm_address_abi_word: the word is addr·2^96 → one div_mod at bit 152
  + one constant mul (was explode(20)).
- numeric_abi_word: B32{lo: value, hi: 0} + native reverse IS the BE
  rendering (was explode(16) + rebuild).
- abi_word_to_uint128[_guarded]: reverse + div_mod at 128; value = the
  low half, head-check = high half == 0 (was explode(31) + BE fold).
- abi_word_low20: word >> 96 = one div_mod at 96 + hi re-shift (was
  explode(31) + rebuild).
- construct_notification_v1: the Bytes<128> payload's 31-byte limbs
  align with the caller address — limb = caller.lo verbatim, next limb
  = caller.hi + a compile-time constant (depth ‖ path at weights
  2^8..2^47), rest zero. One add (was explode(31) + from_le_bytes(128),
  the whole 160-instruction "signet: notification" region).

Remaining targets after pass 1 (from the refreshed profiles):
1. Serializer re-limbing (the singleton's "event serialize + emit" is
   98% of respond's instructions: byte-explode + reconstitute across
   31-byte limb boundaries). Same disease, needs a Serializer that
   tracks byte offsets and splits input limbs with ≤2 div_mods at
   output-limb boundaries instead of full explosion. Applies to the 3
   singleton circuits (and the events experiment).
2. What's left in the vault circuits is PI-coupled (impact ops,
   public_input embeds of the map lookups, constrain_bits on
   arguments) — not reachable by lowering changes; would need
   different public-transcript framing, which PI-equality forbids in
   the differential harness. The eDSL-vs-eDSL freedom starts where
   compact-compatibility ends; note for the M7 write-up.
