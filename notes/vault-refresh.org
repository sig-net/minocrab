#+title: M28 — the vault re-ported to the Poseidon protocol (sig-net refresh)

What upstream shipped and what the Signet module / test caller / signet-sim
did about it is in milestones.org M28 (rewritten 2026-09-05) and
notes/benchmark.org §2026-09-05. This note is the vault re-port itself:
the decisions, the as-built record per rung, and what the harness now is.

* 0. The fork verdict (2026-09-05): =_opt=, =_borsh=, =_modern= RETIRED
M28 A asked: "decide whether they survive at all now that upstream adopted
their avenues". They do not, and the reasons are each sufficient alone:

1. THEIR ANCHOR IS GONE. All three were forks OF the compat port, keyed to
   the nine-circuit vault (=initialize=, =deposit=, =claim=, =approveRouter=,
   =withdraw=, =completeWithdraw=, =refund=, =swap=, =completeSwap=) and
   asserted against it by the fork ledgers (=erc20_vault_opt_fork.rs=,
   =erc20_vault_borsh_fork.rs=, =erc20_vault_modern_fork.rs=: "byte-identical
   to the parent or a declared divergence"). The corpus at =0d9c1660= has
   no such artifacts: seventeen circuits under new names, a 21-field
   ledger, per-flow refunds. Re-porting the compat lineage necessarily
   re-shapes =VAULT= and the record types the forks import, so keeping
   them would have meant re-porting FOUR vaults, three of them to a layout
   no deployment has.
2. UPSTREAM ADOPTED THEIR AVENUES. The =_opt= fork's Poseidon refund
   commitment (rung 5(v)) and the identity commitment's move away from the
   two-block SHA are now the protocol (=refundCommitment= and
   =userCommitment= are =upgradeFromTransient(transientHash(…))= in the
   source); the split of =refund= into per-flow circuits is upstream's
   too. The remaining opt avenues (one =kernel.self= read, the encoded
   domain separator, the single-claimed-spend burn, the derived change
   nonce) live on in =erc20_vault_pending=, and so does the whole =_borsh=
   wire format (=Response::KIND=, the V2 record, =CircuitBorsh= outputs).
3. THE PENDING LINEAGE IS THE API'S EXPRESSION of the new protocol and is
   green (M35 C; notes/benchmark.org §2026-09-05: request circuits at
   0.14-0.35× of compactc's rows, settles at 0.86-0.88×). The =_modern=
   showcase that README pointed at is superseded by it.

What was kept, and where it went:
- =RESPONSE_KIND_*=, =RESPONSE_KINDS=, =VAULT_TOKEN_TAG=, =VaultEventV2= /
  =SwapEventV2= → =erc20_vault_pending= (the format's carrier). The
  serialization-conformance suite (=spec/borsh-subset.md='s executable
  half) and =tests/serialization/records.rs= import them from there.
- The harness's =Art= enum keeps its four variants as CONCRETIZATION
  selectors (the discretionary hash constructions and the V2 record shape
  in =tests/vault/prims.rs= / =model.rs=), because the conformance suite
  generates V2 records through =with_art(Art::Borsh)=. =ARTS= — the
  artifacts a case is RUN against — is =[Art::Compat]=. =Circuit::build=
  panics for the retired variants by name.
- The bench has two sides again (=minocrab=, =compactc=); =Preimages::PerSide=
  stays for the next side that cannot share a statement.
- =tests/erc20_vault_pending.rs='s cost rule now compares against the
  modern lineage's LAST frozen rows (row_snapshot at abb4cfb) rather than
  building it.
- Deleted outright: the three sources (5,219 lines), the three fork gates,
  =erc20_vault_opt_burn_wellformed.rs= (the single-claimed-spend burn's
  ledger proof — its subject, =common::burn_spend=, is still used by the
  Pending lineage; the proof is in git at abb4cfb and its argument in
  =burn_spend='s doc comment), =borsh_map_aliasing.rs= (a lint over two
  deleted files).
- README's side-by-side now shows =erc20_vault_pending::deposit=.

Not lost: the M10 measured ladder (notes/vault-optimization.org), the M11
format decisions (notes/borsh-format.org) and BENCHMARK.md's four-sided
run are history and stay as written; BENCHMARK.md is re-run under M28 C.

* 1. The re-port, as built (2026-09-05, branch =m28-vault=)
** What the compat lineage is now
=crates/minocrab-contracts/src/erc20_vault.rs=: the seventeen circuits of
signet-midnight-examples =0d9c1660=, instruction order following the
Compact source, every one PI-equal to compactc's artifact
(=tests/erc20_vault_differential.rs=: 57 tests — per circuit a
matches-corpus run, the guard failures both artifacts must reject, and
the tamper sweep with zero acceptance disagreements).

The block is 21 fields and compactc SEGMENTS it (six at =[0, i]=, fifteen
at =[1, i − 6]=). =#[derive(Ledger)]= computes the same paths — this is
the first compactc-anchored proof of the segmentation code (the Pending
lineage exercised it, but had no twin). Five settle views are
=#[derive(LedgerRepr)]= structs in maps; the request record types are
one =EventRecord= instantiation per calldata shape (2/7/2/3 words).

What changed in the port relative to the nine-circuit vault, and what it
cost nothing: the notification's depth and path bytes are read off the
map handle (=LedgerMap::field_path()=), so no circuit spells =[1, 3, 0,
0]=; the request assembly, freshness check, record insert and notify are
four shared functions; the =evmChainId= read is made by the caller at the
struct literal's position (compactc reads it BEFORE a =to= that is a cell
— the one ordering the first differential run caught, in =approveStata=).

** Two upstream facts the port had to follow exactly
- =completeWithdraw= now witnesses the caller's secret UNCONDITIONALLY
  (the commitment is hoisted out of the =if=), and asserts it only on the
  refund branch. On the success branch the witness is read by nothing in
  either artifact, so the differential's success-case sweep is transcript-
  only (a perturbed secret is accepted by both; that is upstream's
  "anyone may settle a succeeded withdrawal", not a gap of ours).
- =startRedeem= reads =vaultEvmAddress= TWICE (once per calldata word the
  source names it in); compactc does not CSE ledger reads.

** The harness (=tests/vault/=)
Rewritten around ONE concretization. =ops.rs= holds the segmented op
shapes (transcribed from the artifacts; the oracle the eDSL's ledger
methods are checked against, so not built from them). =model.rs=: an
=Env= (the cells every circuit may read + the call context), a =Req=
(record limbs → Poseidon id → aligned value), seventeen scenarios; popeq
outputs are DERIVED from the op stream (=ops::outputs_of=), so a scenario
cannot list an output its ops never read. =exec.rs= builds the segmented
state tree and resolves a flat field index through it. =spec.rs=: the
seventeen spec functions with CONCRETE effects (no =Term=/=Art=).
=gen.rs=: branch-aware strategies for all seventeen.
=tests/erc20_vault_spec.rs=: five links per generated case — acceptance,
reference VM, compactc's artifact through the comparator, PI/transcript
length closure, and the ledger's own =Effects= (17 properties, green at
the default 48 cases and at =PROPTEST_CASES=2000= in release: 34,000
cases, 17.5 s). =tests/erc20_vault_adversarial.rs=: the families
that survive the format change — argument/witness malleability on
=completeDeposit=, =s = 0= and =n=/low-s on every settle circuit, the
identity response key (still accepted by compactc's =initialise=, so by
ours), wrong-flow settles, the forged-membership/ledger case, the four
refunds against success-shaped outputs, the 0x02 hazard (kept by
upstream), Poseidon injectivity on the generated corpus, completeSwap's
underflow boundary (19 tests).

** What the Borsh spec suite lost and kept
=serialization_conformance= still proves the record BYTES (deployed and
V2) and the attestation-preimage bytes are canonical Borsh. The
=keccak256(borsh(record)) == request id= equalities are GONE: the id is
Poseidon over the field-aligned limbs since =fff3421c=, not a function of
the bytes. =spec/borsh-subset.md= §5/§6 carry a dated "superseded hash
rule" note; the vectors' =keccak256= field is now documented as a
checksum. A proper revision of the spec's hash sections is an open item
(below). The borsh-fork-only property (V2 attestation preimages through
the fork's model) went with the fork; the V2 output encoding is covered
by the Pending lineage's =CircuitBorsh= tests.

* 3. Upstream's hoisted witness in =completeWithdraw= — measured (2026-09-05)
The source comment: "These hashes sit outside the if on purpose: the
proving circuit evaluates both branches, so hoisting them keeps the
circuit to one copy of each hash." Checked by compiling a variant with
=myCommitment= (and so =callerSecretKey()=) and =domainSep= moved back
inside =if (!succeeded)= with the pinned compactc
(scratch, not committed):

| | upstream =0d9c1660= | variant (inside the if) |
|---|---|---|
| k / rows | 16 / 40,553 | 16 / 40,553 |
| instructions | 187 | 187 |
| transient_hash / persistent_hash | 3 / 2 | 3 / 2 |
| private_inputs (guarded) | 4 (2) | 4 (4) |

Identical cost. There is ONE branch and one use of each hash, so nothing
is duplicated either way — the rationale in the comment does not apply
to this circuit (it may have been carried over from a two-branch
sketch). The only effect of the hoist is semantic: the caller's secret
is consumed unconditionally and left unchecked on the success branch,
which is what changed the analysis draft's Gap 2 at the witness level
(notes/zkir-semantics.org §7.1, V5). A one-line upstream PR (move the
two =const=s back inside the =if=, delete the comment) restores the
draft's stated property at zero cost; dmd to decide whether to raise it.
Whatever upstream ships, the compat port follows it (PI-equal).
