* What ZKIR is

ZKIR ("zero-knowledge intermediate representation") is Midnight's circuit IR:
a flat, SSA-ish list of instructions over BLS12-381 scalar-field values
(=Fr=), with private/public input declarations, constraints, hashes, and EC
ops. The Compact compiler emits one ZKIR program per exported circuit; a
separate ZKIR compiler (the =zkir= binary) lowers each program to a PLONK
circuit (midnight-zk / halo2-descended, KZG commitments, BLS12-381) and
produces prover/verifier keys. The prover (locally or in the proof server)
re-executes the ZKIR with a witness transcript (=ProofPreimage=) to build the
proof.

- Docs one-liner: "the bridge between Compact and the ZK backend ...
  intermediate circuit representations used by the proof server"
  https://docs.midnight.network/getting-started/hello-world
- Compiler docs: "produces proving circuits in a zero-knowledge intermediate
  language (zkir), and it uses a zkir compiler to produce proving keys for
  each such circuit" https://docs.midnight.network/develop/reference/compact/lang-ref

* Where ZKIR is defined (the spec is the Rust code)

There is *no standalone prose spec document* for ZKIR. (The =spec/= directory
of midnight-ledger covers the ledger, Impact/onchain-runtime, FAB, cost
model, zswap — not ZKIR; the Compact =specification/= dir covers the Compact
language.) The de-facto spec is the Rust source, which is well doc-commented
per instruction:

- Repo: https://github.com/midnightntwrk/midnight-ledger (Apache-2.0)
  - =zkir/= — ZKIR *v2*. Crate =midnight-zkir= (workspace version 2.1.0;
    crates.io max published 2.1.0: https://crates.io/crates/midnight-zkir).
    - =zkir/src/ir.rs= — =IrSource= (the whole program), =Instruction= enum,
      =IrMinorVersion=, JSON (serde) + binary (tagged) serialization,
      prover-key generation, =Model= (k / row counts).
    - =zkir/src/ir_vm.rs= — an IR interpreter/preprocessor (=Preprocessed=)
      used to evaluate the IR against a transcript.
    - =zkir/src/main.rs= — the =zkir= CLI binary (see below).
  - =zkir-v3/= — ZKIR *v3*. Crate =midnight-zkir-v3=, version 3.0.0-rc.1
    in-repo; *not on crates.io* (checked 2026-08-13: "crate midnight-zkir-v3
    does not exist"). Layout: =ir.rs=, =ir_types.rs=, =ir_instructions/=
    (one module per op), =ir_vm.rs=, =main.rs=.
  - =zkir-wasm/=, =zkir-v3-wasm/= — WASM proving bindings for v2/v3.
  - =zkir-precompiles/= — exists in the tree (contents not examined).
  - =CHANGELOG_zkir.md= — IR version history.
- The =Zkir= trait (the prover-facing interface an IR must implement) lives
  in =transient-crypto/src/proofs.rs= (crate =midnight-transient-crypto=,
  crates.io 2.1.0): =check(&self, &ProofPreimage)= and
  =async prove(rng, params, ProverKey<Self>, &ProofPreimage) -> (Proof, Vec<Fr>, skips)=.
  =impl Zkir for IrSource= is in =zkir/src/ir.rs=.

* On-disk formats

** =.zkir= — JSON (human-readable)
Emitted by compactc into =managed/<contract>/zkir/<circuit>.zkir=. Top-level
object (confirmed against
=LFDT-Minokawa/compact/examples/outputs/election.compact/zkir/add_voter.zkir=):

#+begin_src json
{
  "version": { "major": 2, "minor": 0 },
  "do_communications_commitment": true,
  "num_inputs": 2,
  "instructions": [
    { "op": "constrain_bits", "var": 0, "bits": 8 },
    { "op": "load_imm", "imm": "01" },
    { "op": "private_input", "guard": null },
    ...
  ]
}
#+end_src

Instruction encoding is serde with =#[serde(rename_all = "snake_case", tag = "op")]=
on =enum Instruction= (zkir/src/ir.rs). Loading is version-checked in
=IrSource::load= (zkir/src/ir.rs ~line 531): major must match, minor is
carried as =IrMinorVersion=.

** =.bzkir= — tagged binary
Same =IrSource=, serialized with midnight-ledger's own =Serializable= /
=tagged_serialize= framework (crate =midnight-serialize=), tag string
=ir-source[v2-generic]= (older: =ir-source[v2]=). Introduced in zkir 1.1.1
"to be used in sending to the proof server" (CHANGELOG_zkir.md). The =zkir=
CLI transparently converts: reading a =.zkir= writes a sibling =.bzkir=
(=maybe_bzkir= in zkir/src/main.rs).

** Keys
=zkir compile / compile-many= writes =<circuit>.prover= and
=<circuit>.verifier= (tagged-serialized =ProverKey= / =VerifierKey=) into the
=keys/= dir (zkir/src/main.rs, lines ~221-267). compactc places them in
=managed/<contract>/keys/=.

** ZKIR v2 instruction set (from zkir/src/ir.rs)
Assert, CondSelect, ConstrainBits, ConstrainEq, ConstrainToBoolean, Copy,
DeclarePubInput, PiSkip, EcAdd, EcMul, EcMulGenerator, HashToCurve, LoadImm,
DivModPowerOfTwo, ReconstituteField, Output, TransientHash, PersistentHash,
TestEq, Add, Mul, Neg, Not, LessThan, PublicInput, PrivateInput.

** ZKIR v3 instruction set (from zkir-v3/src/ir.rs)
Encode, Assert, CondSelect, ConstrainBits, ConstrainEq, ConstrainToBoolean,
Copy, Impact, EcMul, EcMulGenerator, HashToCurve, IntoCoordinates,
FromCoordinates, IntoBytes32, FromBytes32, Bytes32IntoLowHigh,
Bytes32FromLowHigh, DivModPowerOfTwo, ReconstituteField, TransientHash,
PersistentHash, Keccak256, TestEq, Add, Mul, Neg, Inv, Not, LessThan,
JubjubScalarFromNative, PublicInput, PrivateInput, Output.
Notable: typed values (=ir_types.rs=), an =Impact= instruction (public-input
blocks tied to the on-chain VM; v2 modeled these as separate impact
instructions — see compact CHANGELOG entry for toolchain 0.32.107 "The
generated zkir reverted back to having separate impact instructions"),
=Keccak256=, secp256k1 support, and per-instruction modules under
=ir_instructions/=.

* Pipeline: where ZKIR sits

#+begin_example
  foo.compact
      |  compact compile  (devtools CLI `compact`, Rust, tools/compact in LFDT-Minokawa/compact;
      |                    downloads + runs a pinned toolchain)
      v
  compactc (wrapper script) -> compactc.bin   (the actual compiler, Chez Scheme)
      |   emits managed/<contract>/
      |     compiler/contract-info.json   (interface description, versions)
      |     contract/index.cjs + .d.ts    (TS/JS tx-construction code, uses
      |                                    @midnight-ntwrk/compact-runtime)
      |     zkir/<circuit>.zkir(+.bzkir)  (one IR per exported circuit)
      |     keys/<circuit>.prover/.verifier
      |
      |   key generation is done by shelling out to the bundled `zkir` (v2)
      |   and `zkir-v3` binaries (both ship inside the compactc release zip;
      |   they are the bin targets of midnight-ledger's zkir / zkir-v3 crates)
      v
  proving: ProofPreimage (witness transcript produced by running the compiled
  circuit in the Compact runtime) + IrSource (.bzkir) + ProverKey
      -> transient_crypto::proofs::Zkir::prove  (locally via midnight-zkir, or
         via the proof server, which wraps the same code over HTTP:
         midnight-ledger/proof-server, endpoints /prove, /check, /health, /ready)
      v
  Proof embedded in a Midnight transaction (midnight-ledger); on-chain the
  public transcript is executed by the Impact VM (onchain-vm) and the proof is
  verified against the circuit's verifier key stored in contract state.
#+end_example

* Cross-contract calls: which version

*Answer: Compact toolchain 0.33.0 (language 0.25.0), which targets Midnight
ledger 9. Not available in 0.31.x / ledger 8 (current Mainnet).* As of
2026-08-13 the newest 0.33 artifact is the pre-release =compactc-v0.33.0-rc.2=
(2026-07-15); release notes for final 0.33.0 are dated 2026-07-21 in-repo but
no final tag exists yet, and docs still list 0.31.1 as latest tested.

Details:
- Language design: CoIP-2 "Contract Types, Values, and Calls"
  https://github.com/LFDT-Minokawa/compact/blob/main/coips/coip-0002.md
  (Draft, created 2026-05-27). Language features: =contract= type
  declarations, =contract implements C;=, contract references as first-class
  values (usable in ledger collections), and =reference.circuit(args...)=
  calls. First landed in internal toolchain 0.32.105 (CHANGELOG.md).
- Runtime machinery (compact-runtime 0.18): =crossContractCall= in
  =runtime/src/contract.ts=; =ContractStateProvider=; restructured
  =CircuitContext= with =callContext=, per-address =queryContexts= /
  =gasCosts=, =callProofDataTrace=; dynamic guards (re-entrancy,
  verifier-key binding via SHA-256 =expectedVk=, purity, no-witness callee);
  linking transcript entry =Kernel.claimContractCall=. Callee Zswap
  operations enabled in toolchain 0.33.119 (CHANGELOG.md, issue #658).
- Compiler pass: =compiler/circuit-passes/desugar-contract-calls.ss=.
- Cross-contract calls do *not* require ZKIR v3 — the 0.33.0 release notes
  present CCC and =--feature-zkir-v3= as independent features, and ZKIR v2
  already carries =do_communications_commitment= (the cross-contract
  communication commitment) in every =.zkir= file. (Interplay under v3 uses
  the same mechanism. UNVERIFIED: whether any CCC edge cases are v3-only.)
- Ledger side: contract calls / call prototypes are specified in
  =midnight-ledger/spec/contracts.md= ("contract call" well-formedness,
  claimed calls by address/entry point/communication commitment). The
  release notes bind working CCC to ledger 9.
- History: Compact 1.0-era docs said "Compact 1.0 does not fully implement
  declarations of contracts and the cross-contract calls they support"
  (https://docs.midnight.network/develop/reference/compact/lang-ref); old
  compiler changelog entries (0.23.10x) explicitly called CCC "not yet fully
  supported".

Implication for MinoCrab: to support cross-contract calling we must target
*ledger 9 semantics* (midnight-ledger tags =ledger-9.x=, onchain-runtime v4
line) and, for artifacts compatible with the 0.33 toolchain, emit ZKIR v2 or
v3 with communications commitments plus the =Kernel.claimContractCall=
transcript ops.

* Misc facts worth remembering
- compactc is written in Chez Scheme (built via chez-exe + nanopass;
  =compiler/*.ss=); the devtools CLI is Rust.
- =compact compile --skip-zk= exists per docs to skip key generation
  (UNVERIFIED flag name against current usage page; see
  =doc/compiler-usage.mdx= in the repo).
- contract-info.json ("compiler/" output dir) carries version numbers and
  exported circuit signatures; used by tooling and (since 0.23.103) by
  cross-contract calls: =compiler/manifest-passes=, save-contract-info.
- A =contract-manifest.json= with file hashes is also emitted (CHANGELOG
  toolchain 0.32.108).
- The Compact language spec sources live in
  =LFDT-Minokawa/compact/specification/= (rendered HTML in-repo);
  grammar/reference docs in =doc/=.
